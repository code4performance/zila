AI

use ai talks to a language model: the Anthropic Messages API (ai.anthropic) or any OpenAI-compatible server (ai.openai_compatible), including local ones such as Ollama over plain http. It is written in Brasa on web and json; nothing in the compiler knows about models. The program names the model every time; the library has no default.

Chat and streaming

use ai

let key = try ai.key_from_env("ANTHROPIC_API_KEY")
let client = ai.anthropic(key)
let reply = try client.chat(ai.request("claude-sonnet-5-5", [ai.user("Hello")], 200))
print(reply.text, reply.usage.input, reply.usage.output)

let streamed = try client.stream(req, func(piece)
    print(piece)
    return
end)

ai.request(model, messages, max_tokens) builds a request; set system, temperature (below zero means "the provider's own") and stop on the record. chat returns a Reply with text, stop (End, MaxTokens, ToolUse or Other(text)), usage and the calls the model made. stream calls your function with each piece of text as it arrives (server-sent events) and returns the same Reply at the end; the function may return an error to stop the stream, which closes the connection.

The key is read with ai.key_from_env(name) (an error that names the variable when it is unset) and travels only in a request header: no error message contains it. https is always checked by tls. A failed request has a kind from its status: Unauthenticated (401), PermissionDenied (403), InvalidInput (400, 422), NotFound (404), Unavailable (429 and 5xx) and Timeout after timeout milliseconds. Connection errors, 429, 500, 502, 503, 504 and 529 are retried with back-off (max_retries, 2 by default; retry-after is honored), but never after streamed text reached your function.

A value of your own type

use json

type Invoice = record
    #[desc("the invoice number as printed")] number: text
    total: float
    paid: bool
    note: text?
end

let invoice = try ai.ask(Invoice, client, req)     // Invoice or error

ai.schema(T) makes a JSON Schema from the type at build time, with the field attributes #[desc("...")], #[json("name")] and #[json(skip)]; an optional field is not required, an enum is enum or oneOf. ai.ask puts the schema in the system text, asks for JSON only (a Markdown fence is removed), and parses the answer with json.parse. If it does not parse, the model is shown the error once and asked again; a second failure is an error of kind InvalidInput that carries the answer. The program that calls ask or tool also writes use json, because the generated code names it.

Tools and the agent loop

type City = record
    #[desc("the name of a city")] name: text
end

let tool = ai.tool(City, "get_weather", "The weather in a city", func(c)
    return "sunny in {c.name}"
end)
let run = try client.run(req, [tool])
print(run.reply.text, run.steps)

A tool's input is a record: its fields make the schema the model sees. client.run sends the conversation and, while the model asks for tools, runs them (the calls of one turn run at the same time, and their results go back in order) until the model answers without asking. A handler that returns an error, arguments that do not match the record, and a tool name that does not exist are all reported to the model as error results; they do not end the loop. After max_steps model calls (10 by default) the loop stops with an error. The Run holds the final reply, the whole conversation, the number of steps and the total tokens.

Embeddings

client.embed(model, inputs) returns one []float per input, in order, for OpenAI-compatible servers (batch_size, 64 by default, inputs per request). The Anthropic API has no embeddings endpoint, so ai.anthropic gives an error of kind InvalidInput that says so. client.embedder(model) is a value with the method embed(inputs), which the retrieval code of a later library asks of an embedder.

Safety notes

  • Text from a model, and the output of tools, is untrusted input. A document a tool returns can contain instructions; the library never runs anything the model says except calling the tools you registered.
  • Register only the tools you are willing to have called, and give each the least privilege that works: a read-only database user for a tool that reads.
  • max_tokens is required and max_steps limits an agent, which together bound the cost of a run; usage says what was spent.
  • Keep keys in the environment, not in source files.
