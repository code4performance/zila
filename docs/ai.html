AI

ai, mcp and rag are packages of the Zila Lang repository (packages/) that the compiler embeds, so use ai needs no manifest; a package of your project with the same name replaces them (see Packages).

use ai talks to a language model: the Anthropic Messages API (ai.anthropic) or any OpenAI-compatible server (ai.openai_compatible), including local ones such as Ollama over plain http. It is written in Zila Lang on web and json; nothing in the compiler knows about models. The program names the model every time; the library has no default.

Chat and streaming

use ai

let key = try ai.key_from_env("ANTHROPIC_API_KEY")
let client = ai.anthropic(key)
let reply = try client.chat(ai.request("claude-sonnet-5-5", [ai.user("Hello")], 200))
print(reply.text, reply.usage.input, reply.usage.output)

let streamed = try client.stream(req, func(piece)
    print(piece)
    return
end)

ai.request(model, messages, max_tokens) builds a request; set system, temperature (below zero means "the provider's own") and stop on the record. chat returns a Reply with text, stop (End, MaxTokens, ToolUse or Other(text)), usage and the calls the model made. stream calls your function with each piece of text as it arrives (server-sent events) and returns the same Reply at the end; the function may return an error to stop the stream, which closes the connection.

The key is read with ai.key_from_env(name) (an error that names the variable when it is unset) and travels only in a request header: no error message contains it. https is always checked by tls. A failed request has a kind from its status: Unauthenticated (401), PermissionDenied (403), InvalidInput (400, 422), NotFound (404), Unavailable (429 and 5xx) and Timeout after timeout milliseconds. Connection errors, 429, 500, 502, 503, 504 and 529 are retried with back-off (max_retries, 2 by default; retry-after is honored), but never after streamed text reached your function.

A value of your own type

use json

type Invoice = record
    #[desc("the invoice number as printed")] number: text
    total: float
    paid: bool
    note: text?
end

let invoice = try ai.ask(Invoice, client, req)     // Invoice or error

ai.schema(T) makes a JSON Schema from the type at build time, with the field attributes #[desc("...")], #[json("name")] and #[json(skip)]; an optional field is not required, an enum is enum or oneOf. ai.ask puts the schema in the system text, asks for JSON only (a Markdown fence is removed), and parses the answer with json.parse. If it does not parse, the model is shown the error once and asked again; a second failure is an error of kind InvalidInput that carries the answer. The program that calls ask or tool also writes use json, because the generated code names it.

Tools and the agent loop

type City = record
    #[desc("the name of a city")] name: text
end

let tool = ai.tool(City, "get_weather", "The weather in a city", func(c)
    return "sunny in {c.name}"
end)
let run = try client.run(req, [tool])
print(run.reply.text, run.steps)

A tool's input is a record: its fields make the schema the model sees. client.run sends the conversation and, while the model asks for tools, runs them (the calls of one turn run at the same time, and their results go back in order) until the model answers without asking. A handler that returns an error, arguments that do not match the record, and a tool name that does not exist are all reported to the model as error results; they do not end the loop. After max_steps model calls (10 by default) the loop stops with an error. The Run holds the final reply, the whole conversation, the number of steps and the total tokens.

Embeddings

client.embed(model, inputs) returns one []float per input, in order, for OpenAI-compatible servers (batch_size, 64 by default, inputs per request). The Anthropic API has no embeddings endpoint, so ai.anthropic gives an error of kind InvalidInput that says so. client.embedder(model) is a value with the method embed(inputs), which the retrieval code of a later library asks of an embedder.

MCP: servers and clients

use mcp speaks the Model Context Protocol, the way hosts such as Claude Desktop, Claude Code and IDEs call tools, read resources and use prompts from another program. A server exposes the same ai.Tool values a local agent uses:

use mcp
use ai

let server = mcp.server("customers", "1.0")
server.tool(ai.tool(Search, "find_customer", "Find a customer by name", handler))
server.resource("db://schema", "schema", "text/plain", func() return "..." end)
server.serve_stdio()                              // a host starts the program

var app = web.server(port: 8080)
server.bearer_token = "secret"
try server.serve_http(app, "/mcp")                // Streamable HTTP, on 127.0.0.1
let client = try mcp.connect("http://localhost:8080/mcp", "secret")
let remote = try client.ai_tools()                // for client.run

Over stdio a message is one line of JSON-RPC in each direction and nothing else is written to standard output; requests are handled one at a time. Over HTTP a POST carries a message, sessions travel in Mcp-Session-Id, GET is answered 405 and DELETE ends a session. serve_http makes the web server listen on 127.0.0.1 unless app.host says otherwise, and serving on any other address is an error unless bearer_token was set first. The Origin header must be the same host (or in server.origins), a bearer_token is compared in constant time, and max_message and max_concurrent bound what a client can ask. A tool that fails gives a result with isError; arguments that do not match its input are an invalid-params error (-32602). Lists are paged by cursor, 100 at a time. The client works over HTTP only (starting a child process for stdio needs a process library that does not exist yet).

A server is a way to run code for whoever can reach it. Register only what you want exposed, give each tool the least privilege that works (examples/mcp_server.zila offers narrow parameterized queries and a read-only run_select, never a writable connection), always set a bearer token when the machine is reachable from elsewhere, and remember that what a tool returns is read by a model as untrusted text. This version does not bind the HTTP server to the loopback address by itself.

RAG: answers from your own documents

use rag has the pieces of retrieval-augmented generation as small functions that work with any model client and any store: split documents, embed the pieces, store the vectors, find the closest ones to a question, and ask the model to answer from them.

use rag

let embedder = embeddings.embedder("text-embedding-3-small")
let store = rag.memory_store()
try rag.index(store, embedder, [rag.Document { id: "fees.md", text: body, meta: {} }], rag.index_options())
let answer = try rag.answer(store, embedder, claude, "claude-sonnet-5-5", "What is the fee?", rag.answer_options())
print(answer.text)                       // cites the sources as [1], [2]
for hit in answer.sources
    print(hit.id, hit.score)
end

rag.chunk(text, opts) cuts by size (at most max_chars characters, overlap shared with the next, preferring a paragraph, then a sentence, then a word) or by paragraph, never inside a UTF-8 sequence. An Embedder is anything with embed(inputs) -> [][]float or error, such as client.embedder(model). A VectorStore keeps and searches vectors by cosine similarity: rag.memory_store() (exact scan, save(path) and rag.load_store(path) with a checksum, so a damaged file is an error) or rag.pg_store(conn, table, dims) on PostgreSQL with pgvector (migrate() creates the table and a cosine index; the table name must be a plain identifier). rag.index replaces the earlier chunks of a document and stores nothing of it if the embedder fails; rag.retrieve returns the best hits; rag.search_tool(store, embedder, name, description) offers a store to an agent as a tool.

rag.answer puts each retrieved chunk in a numbered block between random markers that occur in no chunk, tells the model that the blocks are data and not instructions, asks it to answer only from them, and drops the lowest-ranked chunks whole when they exceed max_context_chars. With no chunk found it says so without calling the model. A stored document can still contain text that tries to steer the model: index content you trust, and give an agent that uses search_tool only tools with the least privilege that works. The size limit counts characters, not tokens.

Safety notes

  • Text from a model, and the output of tools, is untrusted input. A document a tool returns can contain instructions; the library never runs anything the model says except calling the tools you registered.
  • Register only the tools you are willing to have called, and give each the least privilege that works: a read-only database user for a tool that reads.
  • max_tokens is required and max_steps limits an agent, which together bound the cost of a run; usage says what was spent.
  • Keep keys in the environment, not in source files.
