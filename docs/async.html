Async

Programs that wait — for time, a file, a network peer — should not freeze while they wait. In Brasa a function that waits is marked async, and await is the one place where a task gives up the processor so another can run. Everything here is compiled natively and needs the Windows target.

async and await

An async func starts running as soon as you call it and returns a Future<T> at once. await waits for the future and gives you its value, without blocking the other tasks.

async func double(n: int) -> int
    await sleep(100)
    return n * 2
end

func main()
    let a = double(1)          // starts now
    let b = double(2)          // starts now, too
    print(await a + await b)   // about 100 ms in total, not 200
end

Rules to remember:

  • await is allowed only inside an async func and inside main; anywhere else the compiler tells you so.
  • A future can be awaited once. Awaiting it again stops the program with future already awaited.
  • An async func cannot take ref parameters: the task works on copies. Pass values or a channel.
  • await does not create futures; it only waits for them. A future you never await still runs, and its result is released when nothing refers to it any more.

Errors

An async function can fail like any other: end its signature with or error. The future then holds a T or error, so try, match and ?? work on the awaited value.

async func parse(s: text) -> int or error
    if s == "bad"
        return error("cannot parse '{s}'")
    end
    return s.len
end

func main() -> error
    let n = try await parse("abcd")           // 4, or return the error
    match await parse("bad")
        ok(v)  -> print("parsed {v}")
        err(e) -> print("failed: {e.message}")
    end
    return
end

Timers and waiting for several things

sleep(ms)
A future that completes after at least ms milliseconds: await sleep(100). Many sleeps overlap; three 100 ms sleeps take about 100 ms.
timeout(ms, future)
A future that gives the awaited value, or an error saying it timed out. If the original future can already fail, you still get a single T or error. The task behind a future that timed out keeps running to the end: there is no cancellation.
await all(futures)
Waits for every future in a list and gives their values in the original order.
await race(futures)
Gives the value of the first future to finish. The others keep running and are released when nothing refers to them.
let xs = await all([after(90, 1), after(30, 2), after(60, 3)])   // [1, 2, 3]
let first = await race([after(300, 1), after(40, 2)])            // 2, after about 40 ms
let r = await timeout(50, after(400, 1))                        // err: timed out

Files

With use fs, reading and writing happen while other tasks keep running: the operating system moves the data and Brasa runs something else meanwhile. Big files are transferred in 64 KiB pieces.

use fs

try await fs.write("notes.txt", "hello")       // creates or replaces the file
let text = try await fs.read("notes.txt")

Errors name the file and give Windows' reason, for example missing.txt: The system cannot find the file specified. Files are closed when the last reference to them goes away.

TCP networking

With use net you can listen, accept, connect, read and write without blocking the other tasks. read gives empty text when the other side closed the connection.

use net

async func echo_server(listener: net.Listener) -> error
    let conn = try await listener.accept()
    let message = try await conn.read(64)
    try await conn.write("echo: {message}")
    await conn.close()
    return
end

func main() -> error
    let listener = try await net.listen(0)          // 0 picks a free port: listener.port
    let server = echo_server(listener)
    let client = try await net.connect("127.0.0.1", listener.port)
    try await client.write("hello")
    print(try await client.read(64))              // echo: hello
    try await server
    return
end

This is examples/async.br in miniature; the full program also reads and writes a file and waits for three sleeps at once. Sockets close when the last reference goes away, or earlier with close(). The first write after the other side closed may still succeed (that is how TCP works); the next one fails with an error.

How tasks run

  • All tasks run on one thread and take turns. A task gives up the processor only at await, when it waits on a channel, with task.yield(), or when it finishes.
  • A task that computes for a long time without awaiting makes every other task wait.
  • async functions, spawn and channels share the same scheduler and can be mixed freely.
  • If every task is waiting and there is no timer or file or network operation in progress, the program stops with fatal: all tasks are asleep - deadlock! and a non-zero exit code. Waiting for a timer is not a deadlock.
  • When main returns the program ends, even if other tasks are still running.

Limits in this version

  • Windows x64 only. A bare-metal kernel that uses async fails to build with a message saying so.
  • No parallelism (one thread) and no cancellation.
  • A future is awaited once.
  • Looking up a host name (not an address like 127.0.0.1) uses the Windows resolver and blocks every task until it answers.
  • Only TCP over IPv4: no UDP, TLS, or directory operations, and the ui message loop does not yet run other tasks.
