Tasks and channels

A task is a function running next to the others. Tasks talk through channels. They are lightweight (thousands are fine), cooperative, and share one scheduler with async/await.

spawn and channel

spawn f(x) starts f as a new task. channel(T) makes a channel carrying values of type T; send puts a value in, receive waits for one, close ends the stream.

use task

func worker(id: int, jobs: Channel<int>, results: Channel<text>)
    while true
        let n = jobs.receive()
        if n == 0
            return
        end
        results.send("worker {id} squared {n} = {n * n}")
        task.yield()
    end
end

func main()
    let jobs = channel(int)
    let results = channel(text)
    spawn worker(1, jobs, results)
    spawn worker(2, jobs, results)
    for i in 1..5
        jobs.send(i)
    end
    jobs.send(0)
    jobs.send(0)
    for i in 0..4
        print(results.receive())
    end
end

How it behaves

  • Tasks run on one thread and take turns. A task gives up the processor only when it waits (receive, await), calls task.yield(), or finishes. A task that computes for a long time makes the others wait.
  • send never blocks: a channel is an unbounded queue.
  • receive waits for a value. On a channel that is closed and empty it returns 0 (or the empty value of its type). Sending on a closed channel stops the program.
  • If every task is waiting and no timer or file or network operation is in progress, the program stops with fatal: all tasks are asleep - deadlock! and a non-zero exit code.
  • When main returns the program ends, even if tasks are still running.
  • Spawn evaluates the call inside the new task, with the variables it uses captured by value when spawn runs.

Limits

  • No parallelism: there is a single thread, so tasks never run at the same instant.
  • Windows x64 only (tasks are Windows fibers); a bare-metal kernel cannot use them.
  • The ui message loop does not yet run other tasks.

For waiting on time, files and the network, use async/await.
