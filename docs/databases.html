Databases

db, postgres and sqlserver are packages of the Zila Lang repository (packages/) that the compiler embeds, so use db needs no manifest; a package of your project with the same name replaces them (see Packages).

Three libraries, all written in Zila Lang on net and tls (no C library is linked): db is what a program uses, postgres and sqlserver are the drivers. A driver's open returns a db.Conn; everything after that is the same on both databases. The library page lists every function; this page shows how they fit together.

Typed rows and parameters

use db
use postgres

type Customer = record
    id: int
    #[db("full_name")] name: text
    email: text?
end

func main() -> error
    let conn = try postgres.open("postgres://app:secret@localhost/shop")
    let rows = try db.query(Customer, conn, "select id, full_name, email from customers where id > $1", db.int(10))
    let one = try db.one(Customer, conn, "select id, full_name, email from customers where id = $1", db.int(7))
    let n = try conn.exec("update customers set email = $1 where id = $2", db.str("a@b.c"), db.int(7))
    return
end

db.query(T, conn, sql, args...) builds a []T and db.one a single T (an error of kind NotFound for no row, InvalidInput for several). A record matches columns to fields by name, ignoring case; #[db("column")] renames a field and #[db(skip)] leaves it out. A column that may be NULL is an optional field (text?); a NULL in any other field is an error that names the row, field and column. Any other type reads a one-column result (db.query(int, conn, "select count(*) ...")). The decoding is written at build time from the shape of the type, like json.

Values never become part of the SQL text: they go to the server as bound parameters, as db.Arg values made with db.int, db.float, db.bool, db.str, db.bytes, db.vector and db.null(). The placeholders are the database's own: $1 for PostgreSQL, @p1 for SQL Server. A bare 5 instead of db.int(5) is a compile error. So a name such as x'); drop table customers; -- is stored as text.

SQL blocks

SQL can be written in the program as it is, the way asm is: a sql line with the name of a dialect, the statement as raw lines, and a line that is just end. The block is a value of type db.Sql.

let min = 10
let city: text? = nil
let q = sql postgres
    select id, full_name, email from customers
    where id > {min} and city = {city}
end
let rows = try db.query_sql(Customer, conn, q)
let n = try conn.exec_sql(q)

Values are parameters. A {expr} in the SQL is never pasted into the text: the compiler writes the dialect's placeholder ($1 for PostgreSQL, @p1 for T-SQL) and the value goes to the server as a bound parameter, converted by its type (integers, float, bool, text, a text? that is nil as NULL, []float as a vector, or a db.Arg as it is). Any other type is a compile error that names it. Braces inside strings, quoted identifiers and comments are text, and {{ and }} write a brace.

Dialects. sql postgres (from use postgres) and sql tsql (from use sqlserver) are the two there are. The compiler reads each block with its dialect's lexical rules and reports, at compile time and with the line, an unterminated string, quoted identifier, comment or dollar-quoted text, unbalanced parentheses, a placeholder written by hand, a second statement where the dialect allows one, and a GO line in T-SQL (a command of client tools, not T-SQL). It does not parse SQL or know your tables: the server stays the judge of the grammar. use db is needed in the file, and a dialect is found only among the packages the file imports.

Running them. conn.rows_sql(q), conn.exec_sql(q), db.query_sql(T, conn, q) and db.one_sql(T, conn, q) behave like the text versions, with the same typed rows, transactions and errors. A connection knows its dialect, and a statement written for another one is an error of kind InvalidInput that names both; nothing is sent. Text statements with db.query and conn.exec keep working.

examples/db.zila writes one query once per dialect and runs it on both servers.

Another database. A dialect is a declaration, not compiler code: a package marks a type with attributes that state the lexical rules (#[sql_dialect("name")], #[sql_placeholder("$n")] or "@pn", ":n", "?", #[sql_string], #[sql_ident], #[sql_line_comment], #[sql_block_comment], #[sql_dollar_quote], #[sql_multi] and a few more), and its connections set dialect when they are made. Oracle, MySQL and SQLite are planned as packages of that kind, with no change to the compiler.

Transactions

let tx = try conn.begin()
try tx.conn.exec("insert into customers(id, name) values ($1, $2)", db.int(99), db.str("Zoë"))
try tx.commit()      // or tx.rollback()

Run the transaction's statements through tx.conn. While it is open, using conn itself, beginning another transaction and using the transaction after it ended are errors. A transaction that goes out of scope without commit or rollback is rolled back before the connection's next statement (a value being dropped cannot wait on the network, so the rollback is sent then).

PostgreSQL

postgres.open("postgres://user:password@host:5432/database?sslmode=require&sslrootcert=ca.pem"). The port defaults to 5432 and the database to the user. sslmode=require is the default: the driver sends the SSLRequest, upgrades the connection with tls.upgrade_with and checks the certificate chain and the host name; if the server refuses TLS, opening fails before any password is sent. sslmode=disable uses plain TCP, for local servers. sslrootcert trusts the certificate authorities of a PEM file for this connection only (it never turns checking off). Login is SCRAM-SHA-256 (the server's signature is verified), md5, or a cleartext password only over TLS.

Statements use the extended query protocol with bound parameters. Results are read completely, up to a million rows (?max_rows=N changes it), then an error; the connection stays usable. db.vector([1.0, 2.5]) sends a pgvector value, and a vector column reads into a []float field:

db.query(int, conn, "select id from items order by embedding <=> $1 limit 1", db.vector([0.1, 0.9, 0.0]))

SQLSTATE codes become error kinds (23505 is AlreadyExists, 28P01 is Unauthenticated, 42501 is PermissionDenied, other 23, 22 and 42 codes are InvalidInput, 08 and 53 are Unavailable), and the message carries the server's text and the code.

SQL Server

sqlserver.open("sqlserver://user:password@host:1433/database?encrypt=strict&cafile=ca.pem"), with SQL login (no Windows authentication, no named instances). encrypt=strict is the default and means TDS 8.0: TLS first, with the ALPN protocol tds/8.0 and the certificate checked (SQL Server 2022 or later, Azure SQL). encrypt=off sends nothing encrypted, the password only obfuscated as TDS defines it: use it for local development. encrypt=on (TLS inside the TDS pre-login) is not supported and is refused before any connection is made.

Named instances. The host may be host\INSTANCE. On this machine (., localhost) with no port, the driver uses the instance's named pipe (\\.\pipe\MSSQL$INSTANCE\sql\query), so an instance with TCP turned off still works; the default is encrypt=off there because a pipe is local, and encrypt=strict over a pipe is refused (a pipe cannot carry TLS). For another machine, the driver asks the SQL Server Browser (UDP 1434) for the instance's TCP port. ?transport=pipe (with an optional ?pipe=...) and ?transport=tcp choose explicitly. Named pipes exist on Windows only. ?timeout=ms cancels a statement that runs longer and gives an error of kind Timeout.

Statements with arguments run as sp_executesql with typed parameters; without arguments, as a batch. Types: integers, bit, float and real, decimal, numeric and money (as text), char and varchar (code page 1252, 1250 or 1251, chosen by the collation's language, or a UTF-8 collation), nchar and nvarchar, xml (as text), the date and time types (ISO 8601 text), uniqueidentifier (text) and binary/varbinary. A column of another type (sql_variant, text, ntext, ...), or single-byte text in another code page, is an error that names the column and the type. Error numbers become kinds: 2627 and 2601 are AlreadyExists, 18456 is Unauthenticated, 229 and 297 are PermissionDenied; the message carries the number, severity and state.

Create, read, update, delete

The same calls cover all four. examples/users_crud.zila does them on a Users table, with optional columns, a unique username, a rolled-back delete and the duplicate-key error:

let insert = "insert into dbo.Users (Id, Username, DisplayName, AuthSource, Role, AccessStatus, CreatedAtUtc) values (newid(), @p1, @p2, N'Local', N'User', N'Active', sysutcdatetime())"
try conn.exec(insert, db.str("ana"), db.str("Ana Souza"))                                  // create
let ana = try db.one(User, conn, "select ... from dbo.Users where Username = @p1", db.str("ana"))  // read
try conn.exec("update dbo.Users set Department = @p1 where Username = @p2", db.str("Vendas"), db.str("ana"))  // update
try conn.exec("delete from dbo.Users where Username = @p1", db.str("ana"))                  // delete

examples/db.zila runs one function against PostgreSQL and SQL Server and prints the same rows.

Servers to try it on

tests/docker/ starts real servers: PostgreSQL 19 with pgvector (TLS and SCRAM only), SQL Server 2025 on a plain port and on a port that forces encryption (TDS 8.0), and two small TLS servers, all on 127.0.0.1 with a development certificate authority and a seeded shop database:

docker compose -f tests/docker/compose.yml up -d --wait
. tests/docker/env.ps1                                      # or: source tests/docker/env.sh
cargo test --test postgres --test sqlserver
docker compose -f tests/docker/compose.yml down -v

You do not need Docker: ZILA_TEST_POSTGRES and ZILA_TEST_SQLSERVER may name any server (a local PostgreSQL, a local SQL Server instance reached through its named pipe, ...). The tests that write use temporary tables, and the CRUD test only touches rows whose username starts with zila-crud-. Nothing in cargo test starts Docker: the tests that need these servers print a skip line when ZILA_TEST_POSTGRES, ZILA_TEST_SQLSERVER, ZILA_TEST_SQLSERVER_STRICT, ZILA_TEST_SQLSERVER_AI or ZILA_TEST_CA is not set. The credentials in that folder are for development only.

Safety notes

  • The password of a URL never appears in an error message: db.redact(url) shows it as ***.
  • TLS certificates are always checked. sslrootcert and cafile add authorities for one connection; there is no switch that turns checking off.
  • Give programs the least database privilege that works (a read-only user for a program that only reads): a bound parameter protects against injection, but not against a statement the program itself should not run.
