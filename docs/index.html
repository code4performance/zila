Brasa

A readable systems-and-application language: explicit error handling, structural interfaces, and zero-cost C interop — syntax that reads like prose, power that reaches down to raw pointers and inline assembly.

What is Brasa?

Brasa is a general-purpose programming language designed to feel approachable while staying honest about what your code actually does. Programs are organized into packages and blocks that end with end instead of braces, so a function, a type, or an if reads as a plain block of statements rather than a thicket of punctuation.

Underneath that readable surface sits a practical, static type system: records, enums (with or without data), and structural interfaces, with generics for reusable code. Errors are values, not exceptions — a function that can fail returns T or error, and try propagates failure up the call stack explicitly, so you can always see where a program might fail just by reading its signatures.

Brasa doesn't stop at the application layer. The same language can drop into unsafe blocks to dereference raw pointers, declare extern "C" functions, and write inline asm — enough to call into existing C libraries, be called from C, or write a naked interrupt handler, without switching languages or reaching for a separate systems-programming toolkit.

Design goals

  • Readable by default. Newline-terminated statements, end-delimited blocks, and method chains that read top-to-bottom.
  • Errors you can see. No hidden exceptions — failure is part of a function's return type (T or error), and propagation (try) is explicit at every call site.
  • Native and tiny. Programs compile straight to machine code, with memory freed by reference counting and no runtime to install: see Native compilation. The same compiler builds native windows with the ui library (see the example) and a bootable kernel: Brasa OS.
  • Waiting without freezing. async/await, timers, files and TCP run on cooperative tasks: see Async. Real parallelism comes from threads, shared data and sync.Mutex: see Threads.
  • A practical type system. Records, enums (with or without data), and structural interfaces (a type satisfies an interface just by having the right methods — no inheritance, no explicit implements).
  • No surprise costs. Records are copied on assignment and call unless passed ref, a temporary borrow that cannot escape the call; lists and maps are values too, copied lazily (writing to a shared list copies it, writing to your own list does not); there's no borrow checker and no hidden allocation magic.
  • Systems-capable when you need it. Raw pointers, unsafe blocks, C FFI, and inline assembly are part of the language, gated behind explicit syntax rather than bolted on.

Who it's for

Brasa is aimed at people who like the explicitness of languages like Go or Rust — typed signatures, errors as values, no hidden control flow — but want a lighter, more conversational syntax day to day. It also targets developers who occasionally need to go low-level: calling a C library, exporting a function for a C caller, or writing a few lines of inline assembly, without leaving the language they write their application code in.

A quick taste

examples/hello.br
package main

use http, db, json

type Customer = record
    id: i32
    name: text
    email: text?
end

func greet(c: Customer) -> text
    return "Hello, {c.name}!"
end

func main()
    var c = Customer{ id: 1, name: "Ana" }
    print(greet(c))

    for i in 1..5
        if i % 2 == 0
            print("{i} is even")
        end
    end
end

Notice the string interpolation ("{c.name}"), the optional field (email: text?), and that every block closes with end instead of braces.
