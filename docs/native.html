Native compilation

The Brasa compiler turns a program straight into x86-64 machine code. There is no C, no Rust and no virtual machine in between, and the program needs no runtime installed: a console program is a few kilobytes and imports only the Windows libraries it uses.

Build a program

brasa-parse examples/hello.br -o hello.exe
./hello.exe

The compiler writes assembly and hands it to ml64 and link from the Visual Studio C++ build tools, which it finds on its own. Windows x64 is the only target for programs; Brasa OS uses a second, bare-metal target. --asm prints the generated assembly instead of building.

What works

  • Integers (int, byte, and sized types such as i32 or u16 for low-level code), bool, text with {interpolation}, []T lists and raw pointers.
  • record types, methods, default and named arguments, variadic ...T parameters.
  • enum with or without data and match, which must cover every case.
  • Errors: -> T or error, try, error("message"), match with ok(v) and err(e), and ??.
  • Closures (they capture by value) and top-level functions passed to C as callbacks.
  • if as an expression, while, for over ranges and lists, break and continue.
  • unsafe, extern "system" calls, asm blocks and #[naked] functions.
  • Tasks and channels, async/await, files and TCP, and the ui library for native windows.

Memory

Heap values (text, records, lists, closures, enums with data, results, channels, futures) are managed with reference counting. A value is freed the moment the last reference to it goes away, including when a function ends early with return, break or try. There is no garbage collector, so there are no pauses.

  • Records are copied when assigned or passed; ref passes the original instead.
  • Lists and closures are shared: assigning a list gives a second name for the same list.
  • A cycle (a record that holds a list that holds the record) is never freed. Avoid building cycles.
  • live_objects() returns how many heap objects are alive, which makes leaks easy to see.
type Point = record
    x: int
    y: int
end

func main()
    let before = live_objects()
    for i in 0..1000
        let p = Point{ x: i, y: 2 }
        let s = "point {p.x}"
        if s.len == 0
            print("never")
        end
    end
    let left = live_objects() - before
    print("objects left: {left}")        // 0
end

Cleaning up: drop

A record can define a drop method. Brasa calls it when the last reference goes away, which is how files and sockets close themselves.

type Handle = record
    id: int
end

func (ref h: Handle) drop()
    print("closing {h.id}")
end

func main()
    let a = Handle{ id: 1 }
    print("working")
end                                   // prints: working, then closing 1

A drop method takes nothing and returns nothing. Records marked #[shared] (used by the standard library for files, sockets and futures) are never copied: every name refers to the same object.

Not supported yet

These parse, but the native compiler stops with a clear message when it meets them:

  • Floating point (float, f64) and fixed-size arrays.
  • Generics and interfaces (the grammar has them; there is no code generation for them yet).
  • Maps ({ "a": 1 }), defer, new, spreading a list into arguments (f(...xs)), and html templates.

The tree-walking interpreter behind --run is separate from the compiler and does not know the native-only features (async, await, ui, fs, net).
