Brasa OS

Brasa OS is a small operating system written in Brasa: a 512-byte boot sector (os/boot.br) and a 64-bit kernel with a text console and a shell (os/kernel.br). It runs straight on the hardware or in an emulator, with no host operating system and no C. The compiler even assembles the machine code itself.

Build and run

brasa-parse --os os/boot.br os/kernel.br -o brasa-os.img
.\os\run.ps1              # boots it in QEMU, with a window
.\os\run.ps1 -Serial      # headless: the shell runs on your terminal

You need QEMU to run the image (winget install SoftwareFreedomConservancy.QEMU, or unpack its installer into %USERPROFILE%\qemu). The kernel itself needs only a PC: the disk image can also be written to a USB stick.

The shell

help
Lists the commands.
echo <text>
Prints the text.
calc <a> <op> <b>
Integer arithmetic with + - * / %. Bad input prints an error instead of crashing.
mem
Shows the heap size (the kernel's own counter) and the number of live objects.
clear
Clears the screen.
reboot
Restarts the machine.
halt
Stops the processor.

Input comes from the keyboard (with Shift) and from the serial port; output goes to the VGA screen and to the serial port.

How it boots

  1. The BIOS loads the boot sector at 0x7C00 in 16-bit real mode.
  2. The sector prints a message, enables the A20 line and reads the kernel from disk to 0x10000 (BIOS int 13h, in pieces of 64 sectors).
  3. It enters 32-bit protected mode with a flat descriptor table.
  4. It builds page tables that map the first gigabyte one-to-one with 2 MiB pages.
  5. It turns on PAE, long mode and paging, then jumps into 64-bit code and from there into the kernel.

The kernel is ordinary Brasa: text, lists, enums, match, try, closures and reference counting all work, because the kernel supplies the heap itself: heap_alloc and heap_free in os/kernel.br are marked #[allocator(alloc)] and #[allocator(free)], and the runtime asks them for every object. A kernel that declares no allocator gets the compiler's built-in size-class heap instead (and heap_bytes()). Hardware access uses unsafe raw pointers (the VGA memory) and asm blocks (I/O ports). Everything print writes goes to the console_write(s: text) function the kernel defines.

Why the boot sector holds assembly

os/boot.br is Brasa source, but its #[naked] function holds asm blocks. The code that runs in 16-bit real mode and switches to long mode needs instructions that the 64-bit code generator cannot produce, so that part is written as assembly lines inside Brasa. Everything after the jump to the kernel is regular Brasa.

  • The kernel cannot use tasks, async, ui, fs or net (they need Windows); the build stops with a message saying so.
  • The kernel has to define console_write(s: text).
  • There is no file system, no interrupts besides a CPU-exception reporter, and no multitasking yet.
