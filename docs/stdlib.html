Library

The everyday operations live in four modules: text, list, format and set; json reads and writes JSON; web is an HTTP server and client. They are written in Brasa itself (see the files in std/), and you use them by name: use text once at the top of the file, then text.trim(s). Nothing is added to the types themselves, so the names never clash with your own functions.

Not all of it is the core. text, list, set, sorted, format, bufio, errors, math, float, fs, net, sync, task, future, thread, sys, reflect and derive are the core of the standard library: the compiler and the runtime rest on them, and their names are reserved. json, crypto, tls, ui, web, ai, mcp, rag, db, postgres and sqlserver follow external formats and services and change faster than the compiler, so they are becoming packages of their own: their sources are in packages/, a package of your project may take their name, and using them as part of the standard library prints a warning. See Packages.

text

use text

let words = text.split("red, green ,blue", ",")         // ["red", " green ", "blue"]
let clean = text.trim(words[1])                    // "green"
print(text.join(["a", "b", "c"], "-"))                 // a-b-c
let n = text.parse_int("42") ?? 0                 // 42; 0 when the text is not a number

A text is immutable UTF-8: len and positions count bytes, a char is one code point and for c in s walks the characters (see Text and characters). Searching, splitting, trimming and replacing compare whole byte sequences, so they work for any UTF-8 text. upper and lower change ASCII letters only; reverse and the padding functions work on characters. A function never cuts a character in half, so what it returns is valid UTF-8. Text that comes from outside (fs, net) is not validated when it is read: from_bytes is the way to check bytes.

FunctionWhat it gives
index_of(s, part)The byte position of the first part, or -1. An empty part is found at 0.
contains(s, part), starts_with(s, prefix), ends_with(s, suffix)true or false.
compare(a, b)-1, 0 or 1, comparing byte by byte. Handy for sorting.
split(s, sep)The pieces between the occurrences of sep, empty pieces included. An empty sep aborts with split needs a separator.
join(parts, sep)The parts with sep between them.
lines(s)The lines of s: cut at a newline, a trailing carriage return removed, no empty last line after a final newline.
trim(s), trim_start(s), trim_end(s)s without spaces, tabs, carriage returns and newlines at the ends.
replace(s, from, to)Every non-overlapping from replaced, left to right. An empty from changes nothing.
repeat(s, n)s n times (empty for n <= 0).
pad_left(s, width, fill), pad_right(s, width, fill)s padded with the one-character fill up to width characters (counted by char_count, so pad_right("ação", 6, ".") is ação..). Longer texts are returned unchanged. A fill that is not exactly one character aborts.

The parsers return a result, so you choose what a bad input means: text.parse_int(s) ?? 0 gives a default, try text.parse_int(s) passes the error on, and match looks at both cases. The message names the text, for example not a whole number: "4x2".

list

use list

let doubled = list.map([1, 2, 3], func(n) n * 2 end)             // [2, 4, 6]
let evens = list.filter([1, 2, 3, 4], func(n) n % 2 == 0 end)    // [2, 4]
let sum = list.reduce(doubled, 0, func(total, n) total + n end)    // 12
let sorted = list.sort_by([3, 1, 2], func(a, b) a < b end)          // [1, 2, 3]

These are generic functions (see Generics): the compiler works out the element type from the list and the result type from what your function returns. They never change the list you give them; they build new lists.

FunctionWhat it gives
map(xs, f)A new list of f(x) for every element. The element type of the result may differ from the input's.
filter(xs, keep)The elements for which keep(x) is true, in order.
reduce(xs, start, f)Combines from left to right: f(f(start, x0), x1) and so on.
any(xs, test), all(xs, test)Stop at the first element that decides the answer. any of an empty list is false, all is true.
find(xs, test)The index of the first element that passes, or -1.
reverse(xs), concat(a, b)The elements in the opposite order; all of a then all of b.
slice(xs, from, to)The elements from from up to (not including) to. Both are clamped to the list.
range(a, b)The integers from a up to (not including) b.
sort(xs), contains(xs, x)sort returns a new list in ascending order of compare for any element type that is Ord (integers, text by bytes, records and enums by their derived or declared order; a NaN goes last), stable, and leaves xs alone. contains is true when some element is == to x (any Eq type). Another element type is a compile error naming the type.
sort_by(xs, less)A new list in order, where less(a, b) says whether a goes before b. It is a stable merge sort, so equal elements keep their order; sorting 100,000 numbers takes a fraction of a second. For texts use text.compare(a, b) < 0.

Every list also has the method xs.get(i), which reads an element without the risk of an abort: it gives the element when 0 <= i < xs.len and nothing otherwise (negative i included). For elements that can be nil (text, records, lists, maps) the result is T?, nil when there is no such element; for numbers, booleans and the like, which have no nil, it is T or error (kind InvalidInput), so xs.get(i) ?? 0 reads naturally. It works on the lists that list.slice returns, too. xs[i] aborts when i is out of range.

math

Integer +, - and * wrap at the width of the type and never fail. When a program needs to know whether the exact result fits, use math and call these; each returns int or error.

FunctionWhat it gives
math.checked_add(a, b), checked_sub(a, b), checked_mul(a, b)The exact result, or an error of kind errors.Overflow when it does not fit in an int.
math.checked_div(a, b)The quotient, an errors.InvalidInput error for a zero divisor, and an errors.Overflow error for MIN / -1.

format

use format

print(format.text("%(<8)|%(>8)", ["apples", format.thousands(12000)]) ?? "")   // apples  |  12,000
print(format.pad_left("7", 3, "0"))                                        // 007
print(format.float(3.14159, 2))                                           // 3.14

A template is a text with % placeholders. % is the next argument, %1 the argument at position 1 (counting from 0), and %% is a percent sign. A layout in parentheses sets the width: %(>8) right-aligns in 8 characters, %(<8) left-aligns, %(^8) centers, %(*^9) centers with * as the fill and %(05) pads with zeros. Text longer than the width is never cut, and widths count characters, not bytes. The arguments are texts: placeholders are not braces because a brace in a text literal starts an interpolation, and the helpers below turn numbers into texts.

FunctionWhat it gives
text(template, args)The template with its placeholders replaced by the list of texts args. It returns a result: a missing argument, an unclosed ( or an unknown layout is an error, never partial text.
fmt(template, a, b, ...)Like text, but the values can be integers, floats, booleans or text, up to eight of them: format.fmt("%(<8)|%(>8.2f)", name, price). A value of your own type is formatted through a pub method to_value() that returns a format.Value, usually format.Text("..."). Without a type letter a value shows the way print shows it.
pad_left(s, width), pad_right(s, width), center(s, width)s filled with spaces to width characters. A third argument gives another fill: pad_left("7", 3, "0").
int(n), hex(n), bin(n)The digits of an integer in base 10, 16 (lowercase) or 2, with no prefix. Negative numbers get a leading -.
thousands(n)The integer with , between groups of three digits: 1,234,567.
float(x, digits)The float with exactly digits decimals, halves away from zero.

With fmt a layout can end with a precision and a type: [[fill]align][0][width][.precision][type]. The types are d (decimal), x and X (hexadecimal), b (binary), , (thousands separators), f (fixed decimals, 6 unless a precision says otherwise) and s (as printed). A precision alone, like %(.2), means f and needs a float. A letter that does not fit the value, such as %(x) on text, is an error that names the letter and the kind of value.

format.fmt("%(08x)|%(>10,)|%(.2f)", 255, 1234567, 3.14159)   // 000000ff| 1,234,567|3.14

set

use set

let seen: set.Set<text> = set.empty()
if seen.add("ana")          // true: it was not there yet
    print("first time")
end
let ids = set.from_list([3, 1, 3])   // two elements

A Set<T> holds values of any type that is Hash (text, integers, records and enums of such types, lists), each at most once, and remembers the order in which they were first added, so a loop over to_list() gives the same order every run. It is a value, like a map: a copy shares its storage until one of them is written, and a function changes the caller's set only through a ref parameter. Types from a module are written with the module name: set.Set<text>. (A set is kept as a map, so an element type that is not Hash, such as float, fails with the map key error.)

FunctionWhat it gives
set.empty(), set.from_list(xs)An empty set (its type comes from the variable's type) or a set of the elements of a list.
s.add(x), s.remove(x)Add or remove an element; the result says whether the set changed.
s.has(x), s.len, s.clear()Membership, the number of elements, and emptying the set.
s.to_list()The elements as a list, in the order they were added.
set.union(a, b), set.intersect(a, b), set.difference(a, b)New sets; the arguments do not change. difference keeps the elements of a that are not in b.
set.is_subset(a, b)True when every element of a is in b. The empty set is a subset of every set.

bufio

use bufio

let b = bufio.input()
b.feed("ab")
b.feed("c\nd")
print(b.take_line())        // abc

The buffers behind the readers and writers of fs and net (see Reading by lines and buffered writing), with no system calls. An input buffer takes text in pieces and hands it out as lines or bytes; an output buffer collects pieces.

FunctionWhat it gives
bufio.input(), b.feed(text), b.finish()An empty input buffer, add text that arrived, and say that no more will come (the last piece of text then counts as a line).
b.has_line(), b.take_line()Whether a whole line is ready, and the next line without its \n or \r\n (empty text when none is ready).
b.take(max), b.take_all(), b.unread()Up to max bytes, everything that is left, and how many bytes are waiting.
bufio.output(), o.add(text), o.len(), o.take()An empty output buffer, add text, the bytes waiting, and everything collected in order (the buffer is empty afterwards).

sorted

use sorted

let scores: sorted.SortedMap<text, int> = sorted.map()
scores.put("carla", 70)
scores.put("ana", 90)
for e in scores.entries()          // ana first: keys come out in order
    print("{e.key} {e.value}")
end
let late: sorted.SortedSet<int> = sorted.set_by(func(a, b) a > b end)   // largest first

A SortedMap<K, V> and a SortedSet<T> keep their entries in key order. They are balanced (AVL) trees, so adding, finding and removing take time proportional to the logarithm of the number of entries, even when keys arrive in order. The order comes from a function less(a, b) (true when a goes before b; write a < b, not a <= b), so keys can be any type you can order, such as records. sorted.map() and sorted.set() order any key type that is Ord (integers, text by bytes, records and enums by their derived or declared compare), and map_by and set_by take your own function. Two keys are the same key when neither is less than the other. Both are shared references (their nodes are #[shared] records): every name for a sorted map sees the same entries.

FunctionWhat it gives
sorted.map(), sorted.map_by(less)An empty map for any key type that is Ord (smallest first), or ordered by your function. The types come from the variable's type. (The ready-made integer and text constructors are gone: write sorted.map().)
sorted.set(), sorted.set_by(less)The same for sets (the integer and text constructors became sorted.set()).
m.put(k, v), m.get(k, default), m.has(k), m.remove(k)Add or replace (true when the key was new), read with a default, test, remove (true when it was there).
m.len, m.clear()The number of entries, and emptying the map.
m.keys(), m.values(), m.entries()New lists in key order; an entry has key and value.
m.min(), m.max(), m.floor(k), m.ceil(k)The smallest and largest key, the largest key at most k and the smallest key at least k. Each gives an error when there is none, so write m.min() ?? 0.
m.range(lo, hi)The keys from lo up to but not including hi.
s.add(x), s.has(x), s.remove(x), s.len, s.to_list(), s.min(), s.max(), s.floor(x), s.ceil(x), s.range(lo, hi)The same operations on a set; to_list() is in order.
sorted.union(a, b), sorted.intersect(a, b), sorted.difference(a, b), sorted.is_subset(a, b)New sets ordered like a (the arguments do not change), and the subset test.

json

use json

type Config = record
    port: int
    #[json("host_name")] host: text
    #[json(skip)] cache: text
    proxy: text?
end

let cfg = json.parse(Config, raw)               // Config or error
let out = json.encode(Config, cfg)               // text or error; also json.encode<Config>(cfg)
let tree = json.parse_value(raw)                // a json.Value, when there is no type

Reads and writes JSON (strict RFC 8259) as a free-form tree or directly into and out of your own types. The mapping is derived while compiling, by library code that reads the type through comptime reflection (see the syntax guide): there is no registration and the compiler knows nothing about JSON. The type is passed as an argument, json.parse(Config, raw), or as a type argument, json.encode<Config>(cfg), which is the only way to write a generic type such as Map<text, int>. See the example.

FunctionWhat it does
json.parse(T, s)T or error: builds a value of T from the text.
json.encode(T, x), json.encode_with(T, x, opts)text or error: the compact text of x, or indented by opts.indent spaces per level. An error for a float that is NaN or infinite.
json.parse_value(s)json.Value or error: the document as a tree. Keys keep their order; a repeated key keeps the last value.
json.stringify(v), json.stringify_with(v, opts)text or error: a tree as compact or indented text. A number that was read and not changed prints exactly as written, including integers beyond 2^53.
json.ValueThe enum with the cases Null, Bool(bool), Number(float, text) (the value and its literal; build one by hand with the empty text as the literal), Text(text), List([]Value) and Object(Map<text, Value>). The cases are used as json.Null, json.List(xs).
json.OptionsOptions { indent: 2 }: spaces per level, 0 (the default) meaning compact.

How types map to JSON, in both directions:

BrasaJSON
recordAn object whose keys are the field names, in declaration order. Unknown keys are ignored; a missing key is an error unless the field is optional.
enum without payloadsA text holding the case name: "Red".
enum case with a payloadAn object with one key, the case name: {"Circle": 2.5}; several payloads are a list: {"Rect": [2, 3.5]}. In an enum with both kinds, each case uses its own form.
[]TA list.
Map<text, V>An object, in insertion order. Other key types are refused when compiling.
T? (for text, lists, maps, records)null or a missing key is nil.
integers (i8 to i64, u8 to u64, int, long)An integral number inside the range of the type: 1e2 and 5.0 read as 100 and 5, 1.5 and 300 into a u8 are errors. Nothing wraps or rounds.
float, f64, f32Any number; written as the shortest text that reads back as the same value.
bool, text, json.Valuetrue or false; a string (UTF-8, escapes handled); anything.

Attributes on a record field: #[json("key")] uses key as the JSON key in both directions, and #[json(skip)] leaves the field out of the output and ignores its key when reading (the field keeps its zero value). Any other content, and two fields that end up with the same key, are compile errors that name the fields.

Errors have the kind InvalidInput. A syntax error says where in the text: expected a text key, found 'x' at line 2, column 3. A value that does not fit the type says where in the document: expected text, found number at $.users[2].email ($ is the root, .key an object member, [n] a list position from 0). The first problem is reported and nothing partial is returned. Limits: nesting deeper than 128 levels is an error (so no input can exhaust the stack), a key that appears twice is an error when reading into a record or a map, and a byte order mark or invalid UTF-8 is rejected.

Each type used with parse or encode adds a little generated code to the program (five types came to about 33 KB of executable). Types nested more than about six levels deep in one call run into the limit of eight generation rounds; flatten the type or split the call. use json works on Windows and Linux alike.

web

use web

var app = web.server(port: 8080)
app.use(web.logger())
app.get("/hello/:name", func(req)
    return web.text(200, "hello {req.param("name") ?? "world"}")
end)
try app.run()                                  // or: let running = try app.start()

let reply = try web.get("http://127.0.0.1:8080/hello/ana")   // reply.status, reply.body

use web is an HTTP/1.1 server, a router, a middleware chain, JSON helpers, an HTTP client and HTML templates, all written in Brasa on net, tls, task and json; the compiler only knows the name. It works on Windows and Linux alike and is not available in a bare-metal kernel. See the REST API example and the web example.

Server

The server runs one task per connection on the scheduler, so a slow client never delays the others. web.server(port: 8080) makes a Server (port 0 picks a free one). Its limits are fields you can set before starting: max_head (16 KiB of header lines; 431), max_line (8 KiB request line; 414), max_body (1 MiB; 413, answered without reading the body), read_timeout (10 s for a request that has started; 408), idle_timeout (5 s between requests on a kept-alive connection; closed silently), write_timeout (10 s) and max_connections (1024; a connection beyond that gets 503 and is closed). Times are in milliseconds, sizes in bytes. A malformed request gets 400, an unsupported method 501. Bodies are read with Content-Length or Transfer-Encoding: chunked (both at once is 400); HTTP/1.1 connections are kept alive unless either side says Connection: close, HTTP/1.0 ones close unless they ask to keep alive; requests on one connection are answered in order. app.run() serves until the program ends; app.start() serves in the background and returns a Running with .port and .stop().

CallWhat it does
app.get(pattern, h), post, put, delete, patchRegisters a handler func(Request) -> Response or error. A :name segment captures one path segment (req.param("name"), percent-decoded) and a final *rest captures the rest. Static segments win over parameters; a trailing slash does not matter. No route for the path is 404; routes for the path but not the method give 405 with an Allow header; HEAD uses the GET route and sends no body.
app.use(m)Adds a middleware func(Request, next: Handler) -> Response or error. The first one added is the outermost; it may return without calling next, change the request it passes or the response it gets back, and it also sees the 404 and 405 answers. web.logger() prints METHOD /path status Nms.
app.on_error(f), app.log_to(f)Replaces the function that turns an error into a response, and the function that receives log lines (print by default).
req.method, path, query, headers, body, paramsThe request. req.query_param(name), req.header(name) (any case) and req.param(name) return text?. Header names in req.headers are lower-cased and a repeated header is joined with , .
web.text(status, s), web.json_text(status, s), web.html_page(status, page), web.not_found(), web.redirect(url), web.redirect_with(status, url)Response constructors. The server adds Content-Length and Connection itself; r.with_header(name, value) adds a header.

Errors

An error returned by a handler or middleware becomes a response through its kind: InvalidInput 400, Unauthenticated 401, PermissionDenied 403, NotFound 404, AlreadyExists 409, web.UnsupportedMedia 415, Unavailable 503, Timeout 504, anything else 500. A 4xx body is {"error": "message"}; a 5xx body is always internal error and the message goes to the log only (app.log_to), so a failing disk path never reaches a client.

JSON

web.read_json(T, req) checks that Content-Type contains json (otherwise the error web.UnsupportedMedia, 415) and decodes the body with json.parse (a body that does not fit T is an InvalidInput error that says where, so 400). web.json(T, status, value) and web.created(T, value) (status 201) encode with json.encode and set Content-Type: application/json; web.json<[]Customer>(200, rows) is the form for a generic type. These functions write code for each type they are used with, like json itself, and that code names json, so a program that calls them also writes use json.

Client

web.get(url), web.post(url, body), web.post_json(url, text) and web.request(method, url, headers, body) return a ClientResponse (status, headers, body, r.header(name)) or an error. http:// goes over net, https:// over tls with certificate and host name checks that cannot be turned off. The reply is read until the connection closes, Content-Length bytes or the last chunk. web.request_with(web.client_options(), ...) sets max_response (16 MiB; the error kind Overflow), timeout (30 s for the exchange after connecting, all redirects together; the error kind Timeout) and max_redirects (5). Redirects (301, 302, 303, 307, 308) are followed only to http and https URLs and never from https to http (web.redirect_allowed(from, to) is that rule); 301 to 303 turn a POST into a GET. A server speaks plain http only: put a proxy in front of it for TLS until tls has a server side.

HTML templates

let page = html
    <h1>Hello, {user}</h1>
    @for item in items
        <li>{item.name}</li>
    @end
end
return web.html_page(200, page)

html ... end is a block form (see the syntax guide) handled by a comptime function of this library. The lines are markup with {expression} holes; lines that start with @ are @for x in xs, @if cond, @else (or @else if cond) and @end, and @@ at the start of a line writes a literal @; {{ and }} are literal braces. Lines are trimmed and joined with newlines. The block evaluates to a web.Safe. A value in a hole is escaped (&, <, >, " and ' become entities) unless it is a Safe (so a nested block is not escaped twice) or is written {raw(expr)}; numbers, booleans, characters and text can be interpolated. A malformed template (@for without @end, an unclosed brace, an unknown directive) is a compile error at the block. web.escape(s) and web.raw(s) are available directly. The escaping covers element text and quoted attributes; it does not make values safe inside unquoted attributes, <script> or <style> contents, or URLs.

crypto

use crypto

let d = crypto.sha256("abc")                      // 32 bytes, in a text
print(crypto.hex(d))                             // ba7816bf...
let mac = crypto.hmac_sha256("key", "data")
let key = try crypto.pbkdf2_sha256("password", "salt", 4096, 32)
let nonce = try crypto.random(16)                // from the operating system
print(crypto.base64_encode(nonce))

Hashes, message authentication, encodings and random bytes for protocols: sha256 (and a streaming sha256_new() with add and finish), md5 (old protocols only), hmac_sha256, pbkdf2_sha256, base64_encode and base64_decode (RFC 4648; the base64url_ forms use - and _ without padding), hex and unhex, equal (constant time: use it for secrets and tokens), random and the byte helpers to_bytes and from_bytes. A binary value (a digest, a key) is a text whose bytes are the data, like what a socket returns; show it with hex or base64_encode. Decoding bad input is an error, never a partial result. It offers no ciphers or signatures. Not available in a bare-metal kernel.

db

use db with a driver (postgres or sqlserver); the Databases page explains how it fits together.

db.query(T, conn, sql, args...)
The rows as a []T or error: a record by column name (#[db("column")] renames, #[db(skip)] leaves out, T? allows NULL), or any other type for a one-column result.
db.one(T, conn, sql, args...)
The one row as a T or error (NotFound for none, InvalidInput for several).
db.query_sql(T, conn, q), db.one_sql(T, conn, q), conn.rows_sql(q), conn.exec_sql(q)
The same, for a db.Sql made by a sql postgres or sql tsql block (SQL blocks): the values in the block are bound parameters. A statement written for another dialect than the connection's is an InvalidInput error.
conn.exec(sql, args...)
The number of rows changed, as an int or error.
conn.begin(), tx.conn, tx.commit(), tx.rollback(), conn.close()
Transactions and closing. A transaction dropped without an end is rolled back before the connection's next statement.
db.int(n), db.float(x), db.bool(b), db.str(s), db.bytes(data), db.vector(xs), db.null()
The values of the placeholders (db.Arg); they are sent as bound parameters, never spliced into the SQL.

A driver builds a db.Conn with db.connection(run, begin, commit, rollback, close), so another database only needs those five functions. Errors carry a kind from errors (Unavailable, Unauthenticated, PermissionDenied, NotFound, AlreadyExists, InvalidInput, Closed) and the server's own text and code. Not available in a bare-metal kernel.

postgres

use postgres

let conn = try postgres.open("postgres://app:secret@localhost:5432/shop?sslmode=require&sslrootcert=ca.pem")

The PostgreSQL wire protocol (version 3) in Brasa. open(url) returns a db.Conn. The URL takes sslmode (require, the default, or disable), sslrootcert (extra authorities for this connection) and max_rows. Login by SCRAM-SHA-256 (server signature verified), md5, or cleartext over TLS. Parameters are bound (extended query protocol, text format); db.vector and vector columns work with pgvector. postgres.on_notice receives the text of server notices (ignored by default).

sqlserver

use sqlserver

let conn = try sqlserver.open("sqlserver://app:secret@localhost:1433/shop?encrypt=strict&cafile=ca.pem")

The TDS protocol in Brasa. open(url) returns a db.Conn. encrypt=strict (the default) is TDS 8.0, with ALPN tds/8.0; encrypt=off is for local development (nothing encrypted); encrypt=on is refused. cafile adds authorities for this connection, max_rows limits a result, timeout (milliseconds) cancels a slow statement. The host may be host\INSTANCE: on this machine the instance's named pipe is used (fs.pipe, Windows only), elsewhere the SQL Server Browser gives the TCP port. SQL login only. Parameters go through sp_executesql as @p1, @p2, ...; the supported column types are listed on the Databases page, and any other type is an error that names the column.

tls: upgrade, ALPN and a private CA

let opts = tls.Options { alpn: ["tds/8.0"], require_alpn: true, ca_file: "ca.pem" }
let conn = try tls.connect_with("db.example.com", 1433, opts)
print(conn.protocol())                                // the protocol the server chose

// start TLS on a connection that already exchanged plain bytes (PostgreSQL's SSLRequest)
let secure = try tls.upgrade(plain_conn, "db.example.com")

tls.connect_with(host, port, opts) and tls.upgrade_with(conn, host, opts) take tls.Options: alpn (protocols to offer), require_alpn (fail if the server selects none) and ca_file (a PEM file of extra certificate authorities, trusted for that connection only; the system's still apply, and the chain and host name are always checked). tls.upgrade(conn, host) starts TLS on an open connection after a plain exchange: read exactly the plain answer first. On failure the connection is closed. Windows and Linux behave the same.

use errors

if e.kind == errors.NotFound
    print("{e.message}")
end

The error kinds (see Error handling). use errors is only needed to name a kind: error("message") and e.kind work without it.

NameWhat it gives
errors.NotFound, PermissionDenied, AlreadyExistsSomething that is not there, that may not be touched, or that is already there.
errors.Unauthenticated, UnavailableWho is asking is not known, and a service that cannot answer right now.
errors.Timeout, CancelledThe time ran out (including timeout(ms, f)), or the system canceled the operation.

Good to know
