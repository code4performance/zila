Library

The everyday operations on text and lists live in two modules, text and list. They are written in Brasa itself (see std/text.br and std/list.br), and you use them by name: use text once at the top of the file, then text.trim(s). Nothing is added to the types themselves, so the names never clash with your own functions.

text

use text

let words = text.split("red, green ,blue", ",")         // ["red", " green ", "blue"]
let clean = text.trim(words[1])                    // "green"
print(text.join(["a", "b", "c"], "-"))                 // a-b-c
let n = text.parse_int("42") ?? 0                 // 42; 0 when the text is not a number

Text is bytes (UTF-8). Searching, splitting, trimming and replacing compare whole byte sequences, so they work for any UTF-8 text. upper and lower change ASCII letters only, and reverse reverses bytes. Positions and lengths count bytes.

FunctionWhat it gives
index_of(s, part)The byte position of the first part, or -1. An empty part is found at 0.
contains(s, part), starts_with(s, prefix), ends_with(s, suffix)true or false.
compare(a, b)-1, 0 or 1, comparing byte by byte. Handy for sorting.
split(s, sep)The pieces between the occurrences of sep, empty pieces included. An empty sep stops the program with split needs a separator.
join(parts, sep)The parts with sep between them.
lines(s)The lines of s: cut at a newline, a trailing carriage return removed, no empty last line after a final newline.
trim(s), trim_start(s), trim_end(s)s without spaces, tabs, carriage returns and newlines at the ends.
replace(s, from, to)Every non-overlapping from replaced, left to right. An empty from changes nothing.
repeat(s, n)s n times (empty for n <= 0).
pad_left(s, width, fill), pad_right(s, width, fill)s padded with the one-byte fill up to width bytes. Longer texts are returned unchanged.
upper(s), lower(s), reverse(s)ASCII capitals, ASCII lower case, and the bytes in the opposite order.
parse_int(s)The whole number in s (optional sign, digits) as int or error. Spaces, separators and values outside the int range are errors.
parse_float(s)The float in s as float or error: 1.5, -2e3, .5, 5., inf, -inf, NaN. The result is the float nearest to the written number, so printing a float and parsing it back gives the same float.

The parsers return a result, so you choose what a bad input means: text.parse_int(s) ?? 0 gives a default, try text.parse_int(s) passes the error on, and match looks at both cases. The message names the text, for example not a whole number: "4x2".

list

use list

let doubled = list.map([1, 2, 3], func(n) n * 2 end)             // [2, 4, 6]
let evens = list.filter([1, 2, 3, 4], func(n) n % 2 == 0 end)    // [2, 4]
let sum = list.reduce(doubled, 0, func(total, n) total + n end)    // 12
let sorted = list.sort_by([3, 1, 2], func(a, b) a < b end)          // [1, 2, 3]

These are generic functions (see Generics): the compiler works out the element type from the list and the result type from what your function returns. They never change the list you give them; they build new lists.

FunctionWhat it gives
map(xs, f)A new list of f(x) for every element. The element type of the result may differ from the input's.
filter(xs, keep)The elements for which keep(x) is true, in order.
reduce(xs, start, f)Combines from left to right: f(f(start, x0), x1) and so on.
any(xs, test), all(xs, test)Stop at the first element that decides the answer. any of an empty list is false, all is true.
find(xs, test)The index of the first element that passes, or -1.
reverse(xs), concat(a, b)The elements in the opposite order; all of a then all of b.
slice(xs, from, to)The elements from from up to (not including) to. Both are clamped to the list.
range(a, b)The integers from a up to (not including) b.
sort_by(xs, less)A new list in order, where less(a, b) says whether a goes before b. It is a stable merge sort, so equal elements keep their order; sorting 100,000 numbers takes a fraction of a second. For texts use text.compare(a, b) < 0.

Good to know

  • Both modules are compiled with your program, so only the functions you use add to its size. They need the Windows target (use text also brings in the float printing library, which is why it is not available in a bare-metal kernel).
  • The interpreter behind --run runs them too. It handles errors only through ?? (it has no match on results), and a lambda in it cannot use variables of the function around it.
  • Not here yet: regular expressions, Unicode case mapping, a format function with placeholders, sets, and sorted maps.
