## 3. Hover, completion, signature help

- [x] 3.1 Position index (uses and declarations with ranges and targets) from the typed tree. Verify: unit test resolves every name in a sample file. Done: `codegen_x64::PositionIndex` (`src/codegen_x64/index.rs`), returned in `Checked::index`: every name of the project's packages as an `IndexEntry { span, name, is_declaration, target: Referent, ty }`, with `at(module, line, col)`, `declaration_of(target)` and `references(target)`. `Referent` is a local (by the range of its declaration), function, method, type, field, variant, global, package, type parameter, built-in, or `Unknown`. The AST gained spans for `for` variables, pattern names and bindings and record-literal field names. Deviation from the wording "from the typed tree": the typed tree has holes (`Opaque` statements, no `match` on some paths), so the index is built by a walk over the syntax tree with its own scopes and the declaration tables, and asks `check_expr` only for the type of a receiver or scrutinee (a name whose meaning needs a type that is not known is `Unknown`, never guessed). `tests/index.rs`: every name of a sample file is in the index, its range covers exactly its text and it resolves (and its declaration is in the index), the meaning of each kind of name, a package of the project; over the 26 examples that build, every range covers its name (1733 names, 69 unresolved: members of the standard library and of built-in collections, generic bodies). The standard library is not indexed (4.1 will add it on demand); a line in a multi-file package is a line of the merged text (gap 11). Unchanged: assembly of the 120 compilations, the full suite apart from the two failures noted in 1.3.
- [x] 3.2 `textDocument/hover` with type and doc comment. Verify: LSP test on a documented function. - [x] 3.3 `textDocument/completion`: scope names, members after `.`, package members, attributes, in a file with an unrelated syntax error.
