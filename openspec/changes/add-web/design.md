## Context

`std/net.br` offers `connect`, `listen`, `Listener.accept`, `Conn.read(max)`, `Conn.write(data)` and a buffered `Reader` (`read_line`, `read`, `read_all`) over `bufio.InBuf`; the scheduler in `std/task.br` provides `task.start`, timers (`add_timer`), `park`/`wake`, and `spawn f(x)`. `std/tls.br` offers `tls.connect(host, port)` with `read`/`write`. `examples/types.br` already declares `Handler` and `Middleware`, and `examples/rest_api.br` shows `app.get`, `req.param`, `http.json`, `http.created`.

The library is plain Brasa: nothing in it needs a new compiler feature except the templating entry point, which uses the generic block form of `add-comptime-reflection`.

## Depends on

- `add-comptime-reflection`: `req.json(T)` and `web.json(status, value)` rely on `json` and its reflection over `T`; `html ... end` blocks are handed to a comptime function (`web.html`) as raw text, and the function returns code.
- `add-json`: `json.parse(T, text)` and `json.encode(value)` do the work; `web` adds no JSON code of its own.
- `add-error-kind`: errors carry a kind (`NotFound`, `InvalidInput`, `Timeout`, ...); `web` maps kinds to statuses and gives its own errors kinds (parse failures are `InvalidInput`, limits use the closest kind that change defines).
- `remove-async-coloring`: the code in this change is written without `async`/`await`; any call may wait. Until that change lands the same code would need `async`/`await` marks on every function that touches `net`.

## Goals / Non-Goals

**Goals:**
- The API of `examples/rest_api.br` works, with `web` instead of `http`.
- A server survives 100 concurrent clients on one scheduler, including slow and misbehaving ones.
- The same behavior on Windows and Linux (the library only uses `net`, `tls`, `task`).
- Every interpolated value in a template is escaped unless the author opts out explicitly.

**Non-Goals:**
- HTTP/2, WebSocket, server-side TLS (`tls` is client-only), compression, multipart forms, cookies and sessions (follow-ups), static file serving, a database library.
- Streaming bodies: request and response bodies are whole `text`, bounded by limits.

## Decisions

1. **One task per connection.** `app.run()` loops on `accept()` and does `spawn serve(conn, app)`; the scheduler already multiplexes them, so 100 clients need no extra machinery. A counter `max_connections` (default 1024) makes new connections beyond it receive `503` and close immediately.
2. **Parsing on `net.Reader`.** The head is read line by line with `read_line` up to `max_head` bytes (default 16 KiB for all header lines, 8 KiB for the request line): over the limit gives `431` (or `414` for the request line). The body is read with `Content-Length` (limit `max_body`, default 1 MiB, `413` when over) or `Transfer-Encoding: chunked` (chunk sizes in hex, trailers ignored, the same total limit). Both present at once is `400`. Methods are an enum `Method` (`Get`, `Post`, `Put`, `Delete`, `Patch`, `Head`, `Options`); any other method is `501`. Header names are compared case-insensitively (stored lower-cased in a `Map<text, text>`); a repeated header is joined with `, `.
3. **Keep-alive and timeouts.** HTTP/1.1 connections stay open unless `Connection: close` is sent or received; HTTP/1.0 closes unless `keep-alive` is requested. After a response the task waits for the next request for at most `idle_timeout` (default 5 s); a request that has started must be complete (head and body) within `read_timeout` (default 10 s). Timeouts use `task.add_timer` to close the connection, which wakes the parked read with an error; a generation counter on the connection makes a stale timer do nothing, so timers need no cancellation. A request that timed out after starting gets `408`; an idle connection is closed silently. Writes have `write_timeout` (default 10 s) the same way.
4. **Records.** `Request { method, path, query: Map<text,text>, headers, body: text, params: Map<text,text> }` with methods `param(name) -> text?`, `query_param(name) -> text?`, `header(name) -> text?`, `json(T) -> T or error`. `Response { status: int, headers: Map<text,text>, body: text }` built by `web.text(status, s)`, `web.json(status, value)`, `web.html_page(status, s)`, `web.created(value)`, `web.not_found()`, `web.redirect(url)`; `web.json` sets `Content-Type: application/json`, the others `text/plain` or `text/html; charset=utf-8`. The server adds `Content-Length` and `Connection`. Percent-decoding applies to path parameters and query values; a bad escape is `400`.
5. **Router.** `app.get/post/put/delete/patch(pattern, handler)`. Patterns are split on `/`; a segment starting with `:` captures one segment, and `*rest` as the last segment captures the remainder. Matching is by method then segments; static segments win over parameters, registration order decides otherwise. No match for the path gives `404`; a match for the path with another method gives `405` with an `Allow` header. `HEAD` falls back to `GET` without a body. Trailing slashes are not significant.
6. **Middleware.** `app.use(m: Middleware)` appends to a chain; the chain is folded once at `run()` into a single `Handler`, outermost first, so `use(a); use(b)` runs `a` before `b`. A middleware may return without calling `next` (short-circuit), change the request, or change the response. Middleware also wraps the 404/405 result, so loggers see every request. One middleware ships: `web.logger()` (method, path, status, milliseconds, to standard output). There is no recover middleware: the language has no panic (`remove-panic-add-abort`), errors are values.
7. **Error mapping.** A handler returns `Response or error`. The server turns an error into a response with `app.on_error(func(err: error) -> Response)`; the default maps by kind: `InvalidInput` 400, `Unauthenticated` 401, `PermissionDenied` 403, `NotFound` 404, `AlreadyExists` 409, `Unavailable` 503, `Timeout` 504, everything else 500. The body is JSON `{"error": "<message>"}` for 4xx and the fixed text `internal error` for 5xx (the message goes to the log, not to the client). Kind names are exactly those `add-error-kind` defines; where that change has a different set, the table follows it.
8. **JSON.** `req.json(T)` checks that `Content-Type` contains `json` (else `415`) and calls `json.parse(T, req.body)`; a parse error is an `InvalidInput` error and so `400` through the mapper. `web.json(status, v)` calls `json.encode(v)`. No JSON code lives in `web`.
9. **Client.** `web.get(url)`, `web.post(url, body)` and `web.request(method, url, headers, body)` return `ClientResponse { status, headers, body } or error`. `http://` uses `net.connect`, `https://` uses `tls.connect` (certificate and name validated by `tls`; no way to turn that off). Requests are HTTP/1.1 with `Connection: close`, reading until close, `Content-Length` or the last chunk, with `max_response` (default 16 MiB) and a total `timeout` (default 30 s). Redirects (301, 302, 303, 307, 308) are followed up to 5 times, only to `http`/`https` URLs; a redirect from `https` to `http` is an error. Host names are resolved by `net`. A server speaks plain `http`; TLS termination is left to a proxy until `tls` has a server side.
10. **Templates: `html` blocks.** A block `html ... end` is the generic block form of `add-comptime-reflection`; the library defines `#[block] comptime func html(raw: text) -> text`. The function parses the raw text at compile time into text runs, `{expr}` interpolations and control lines. Control flow uses lines that start with `@`: `@for u in users`, `@if cond`, `@else`, `@end`; this keeps markup free of ambiguity with `<`/`>`. `{{` and `}}` give literal braces. The generated code appends to a `text` builder: literals as they are, each `{expr}` through `web.escape(to_text(expr))`. `{raw(expr)}` is the only way to insert unescaped text, and a value of type `web.Safe` (a record wrapping text, which is what a nested `html` block returns) is inserted without escaping, so templates compose. Malformed templates (unbalanced `@end`, unclosed `{`, unknown directive) are compile errors at the block's position. The block evaluates to `text`. `web.escape` replaces `& < > " '` with entities, so values are safe in element text and in quoted attributes; unquoted attributes, `<script>` and `<style>` contents and URLs are not covered and the documentation says so.
11. **Registration.** `std/web.br` is one portable file added to the library tables in `src/codegen_x64.rs` (no Linux layer is needed, since `net`, `tls` and `task` have theirs); `use web` is rejected in the bare-metal kernel together with `net`.
12. **Tests.** `tests/web.rs` compiles Brasa programs that start the server and a client in the same program, as `tests/tls.rs` does; requests to the public internet are skipped offline. Pure helpers (`web.escape`, router matching, request parsing from a `text`) are tested through small programs without sockets.

## Risks

- Whole-body buffering means a large `max_body` costs memory per connection; defaults are conservative.
- Reading the head line by line through `net.Reader` copies; acceptable for a first version.
- Slowloris is bounded by `read_timeout` per request and `max_connections`, not by a rate limit.
- The template directive syntax (`@for`) can change before 1.0; templates are rewritten together with the repository.
- `add-error-kind` and `add-json` names may shift in review; tasks refer to them by role and the final names are taken from the merged changes.
