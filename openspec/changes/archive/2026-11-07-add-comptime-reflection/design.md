## Context

Attributes already parse and are kept: `Decl.attrs` and `Field.attrs` hold `Attr { name, args: Vec<Expr> }` (`src/ast.rs`, `Parser::attrs` in `src/parser.rs`), so `#[json("full_name")]` is available to the compiler today and nothing reads it. The lexer already has a raw-capture mode for `asm` blocks (`in_asm`, `asm_line` in `src/lexer.rs`) and the formatter already keeps those lines (`src/fmt.rs`). Generics (`add-generics-and-interfaces`) already give us specialization by cloning a declaration and compiling the clone through the normal paths. The code generator turns a `File` into assembly (`generate_asm_for`) and native output (`compile_to_native_with`, `compile_to_linux`).

What is missing is a way to run user-supplied code at build time. The project is removing its interpreter (`remove-interpreter`), so running comptime code means building and running a real program, which is why this change depends on a fast, tool-free host build (`add-direct-pe-output`).

**Depends on**
- `remove-interpreter`: the reason comptime is compiled native code. Nothing here may call `interp.rs`.
- `add-direct-pe-output`: building the comptime program on Windows without `ml64`/`link`; without it each comptime run would cost a Visual Studio invocation.
- Soft dependencies, which build on this change and are not part of it: `add-json` and `add-derived-eq-ord-hash` (the first users of `#[derive]` and `#[generated]`), `add-web` (the first user of a block), `add-package-manager` (third-party packages are why the subset must be enforced), `add-error-kind` and `remove-panic-add-abort` (how a generator reports failure; this change uses `reflect.fail` and a protocol line so it does not depend on either), `add-visibility-pub` (reflection ignores visibility; generated code is subject to it like any code).

## Goals / Non-Goals

**Goals**
- Libraries add per-type code generation, type-indexed functions and block syntax with no compiler change.
- Deterministic, sandboxed generators safe to run from a third-party package.
- Errors a user can act on: the user's line first, the generated line second.
- Fast rebuilds through a cache.

**Non-Goals**
- Syntax-rewriting macros, or generators that see or return an AST.
- Arbitrary compile-time evaluation of expressions or `comptime` blocks inside functions.
- Reflection over function bodies, function lists, other modules' private items, or target layout.
- Parallel generator execution (generators run one at a time at first).

## Decisions

1. **The API is a built-in type `Type` plus a module `std/reflect.br`.** `Type` is known to the compiler and cannot be stored in runtime values. `reflect` holds the plain records a generator works with (`Field { name, ty, attrs, line }`, `Variant { name, fields, attrs, line }`, `Attribute { name, args }`) and the functions `fresh`, `fail` and `target`. Methods on `Type` (`name`, `kind`, `fields`, `variants`, `element`, `key`, `value`, `inner`, `attrs`) read from a table the driver of the comptime program loads from its input (decision 5). This keeps the surface small: adding a query later is adding one method and one input line.

2. **Four kinds of comptime entry points, one mechanism.** All are `comptime func`s returning `text`, distinguished by an attribute and parameters: `#[derive]` (takes `Type`, returns declarations), `#[generated(gen)]` on a body-less runtime function with `comptime t: Type` (gen takes `Type`, returns the body statements), `#[block]` (takes `raw: text`, returns an expression or statements). A fourth, plain helper `comptime func` called by the others, needs no attribute and is part of the same checked closure. The compiler never calls a comptime function in any other way, so there is exactly one "run a generator" routine in `src/comptime.rs`.

3. **Execution: a child process, not in-process.** The compiler builds one executable per batch of generator calls and runs it as a child. In-process loading (a DLL or `dlopen`'d image) was rejected: Windows PE output here has fixed image base and no relocations (`add-direct-pe-output`), a loader in the compiler would need new code for each OS, and a crash or an endless loop would take the compiler down. A child process gives a hard timeout (kill), a clean crash report and no inherited handles. Startup cost is paid once per batch and is hidden by the cache (decision 7).

4. **The driver program.** For a batch, the compiler synthesizes a small Zila Lang file: `package comptime_run`, `use` of the generators' packages, and a `main` that reads the batch from standard input, calls each generator with the reconstructed `Type` and writes the results to standard output. The generators are normal Zila Lang functions in the user's packages, so the existing compiler builds them unchanged (monomorphization, inlining, optimizer, `defer`). The driver is the only file that touches the console; the subset checker (decision 6) does not apply to it, only to the generators and what they reach. Build target is the host: `Target::Windows` on Windows hosts, `Target::Linux` on Linux hosts, regardless of `--target`.

5. **Wire format.** Input and output are plain line-oriented text, escaped with `\n`, `\\` and `\t`. Input per call: `call <id> <generator> <arg-kind>` then a description of the type: `type <name> <kind> <line>`, `field <name> <typeref> <line>`, `variant ...`, `attr <owner> <name> <arg>...`. Output per call: `ok <id> <byte-count>` followed by the text, or `fail <id> <line> <message>` from `reflect.fail`. Type references inside the description are indices into the described type table, so a field of type `[]Address` can be navigated with `element()` and then `fields()` on `Address`. All types reachable from the reflected type are included, depth-limited by the table (no cycles, since references are indices). Text, not binary, keeps the format easy to dump with `--comptime-dump` and to test.

6. **The comptime subset is a reachability check, not a mode.** After name resolution, `src/comptime.rs` walks the call graph from each generator and rejects the constructs in the spec: `extern`, `asm`, `spawn`, `async`, `await`, channel operations, raw pointer and `unsafe` operations, reads and writes of global `var` (immutable `let` constants are allowed because they are values), and calls into modules whose functions reach any of those (`fs`, `net`, `task`, `sys`, `tls`, `ui`, `bufio`...). Standard modules are not allow-listed by name: the check follows real calls, so `text`, `list`, `format`, `math` pass because they contain none of the forbidden constructs, and `fs.read` fails because it reaches `extern`. Errors print the chain `gen -> helper -> fs.read`. Functions through closures or interface-bound calls are followed conservatively using the same instantiation information generics already compute. Heap allocation and recursion are allowed; they are bounded by decision 8.

7. **Cache.** Key = SHA-256 of: the compiler version string, the host triple, the canonical text of every function in the generator's transitive closure (the same set the subset check computes, printed normalized so comments and whitespace do not matter), the generator name and kind, and the serialized input. Stored as `target/zila-comptime/<key>.out` next to the build output directory (or the system temp directory when there is none), containing the `ok`/`fail` record. A hit skips building and running. Only `ok` results are cached: failures are cheap to recompute and must always print fresh. `--no-comptime-cache` bypasses reads and writes. If the SHA-256 implementation is not already in the standard library for TLS, it is added as a small module in the compiler; the cache is an optimization, so a corrupt or unreadable entry is treated as a miss.

8. **Limits.** A wall-clock timeout kills the child (default 5 s, `--comptime-timeout`), standard output is read through a cap of 1 MiB, and the process is started with a memory limit where the host supports one (Windows job object, Linux `setrlimit`) and without one otherwise. There is no fuel counter because there is no interpreter to count in; a time limit is the honest measure for native code and is stated so in the docs. Recursion is allowed and ends in a stack overflow crash or the timeout, both reported as errors naming the generator. Expansion rounds (a generator's output containing derives or blocks) are capped at 8, with a message listing the chain of generators.

9. **Splicing generated declarations.** Generated source from `#[derive]` and `#[generated]` is parsed into a `File` with the existing parser, wrapped in a synthetic module named `<module>.__gen<n>` that implicitly `use`s the generator's package and the module of the reflected type, and added to the program before `declare`. Methods whose receiver is the reflected type attach to it through the normal method table, so `p.describe()` works in the user's module even though the method lives in the synthetic module. Because user code is parsed before expansion, a call to a not-yet-existing derived method resolves after expansion: `load` runs expansion before `declare`. A collision (same receiver and method name, or same top-level name in the module's own namespace) is reported naming the generator and the earlier declaration.

10. **Hygiene.** Decision 9 gives declarations their own namespace, so a generated `escape` cannot capture or collide with a user `escape`. For local variables inside generated bodies, `reflect.fresh("tmp")` returns `__tmp_<n>` with `n` unique in the build; the `__` prefix is reserved and rejected in user code with a message when used at declaration. Block expansions are the exception: an expression produced by a block is parsed and spliced at the block's position, in the user's scope, because a template must read user variables (`{name}`); the block function is responsible for using `reflect.fresh` for helper locals it introduces.

11. **Type arguments and `#[generated]`.** The parser already accepts explicit type arguments at call sites (`add-explicit-type-arguments`); a `comptime t: Type` parameter takes a type name in the same way and the call site is checked to be a path to a declared type or a type expression such as `[]User`. A `#[generated(gen)]` declaration with no body is treated like a generic template: instances are keyed by `(function, type)`, the generator runs once per key, and its text is parsed as the body and compiled with `t` bound as a type alias to the argument. The return type may mention `t`. Calls pass the remaining arguments at run time as for any function; the comptime parameter is erased from the instance's signature.

12. **Block form.** The lexer cannot know which names are blocks, so the pre-scan is done before lexing the body: the driver reads the file's `use` lines (they come first), loads those packages' headers (the same loader `load` uses, restricted to scanning top-level declarations for `#[block]`) and gives the lexer the set of block names. In the lexer, a line whose only token is a name in that set switches on raw capture exactly as `asm` does (`rest_of_line_is_blank`, then raw lines until a line whose trimmed text is `end`) and the whole thing becomes a `Tok::Block { name, raw, line }`. The parser turns it into `Expr::Block { name, raw, line }` (or a statement when alone on a line); codegen expands it through the same generator routine, with the call's `raw` argument. Raw text containing a line `end` cannot be expressed; a library can offer an escape in its own syntax (`html` does not need one). Formatter and language server run the same pre-scan with the package search path they already have; when a package cannot be found they simply treat the name as an ordinary identifier, so editors never fail because of a missing package.

13. **Formatter and language server.** `src/fmt.rs` re-indents the opening name and the closing `end` and copies content lines byte for byte (like `asm`, but without relative re-indentation). `src/lsp.rs` publishes parser diagnostics only; block content is never parsed by the server and no comptime code runs there, so opening a file from an untrusted package cannot execute anything. Compile-time diagnostics appear only on build.

14. **Diagnostics.** Each expansion records a source map entry: generator name, use site (file and line of the attribute, call or block), and the line count of the generated text. A parse or check error whose position falls inside a generated module is rewritten to: the use-site position, a headline `error in code generated by <gen> for <Type>`, the message, and then the generated line with a caret. `reflect.fail(msg, at)` maps `at` (a type, field or variant) to its `line` from the input and reports it as an ordinary error at that line. `--comptime-dump` writes each generated text to standard error prefixed by a header with the key, so users can see and copy what was compiled.

15. **Grammar.** `zila.ebnf`: delete the `Stdlib syntax extensions` section with `html_expr`; add `comptime` to `func_decl`, `[ 'comptime' ] param` for parameters, `Type` to type names, and `block_expr = ident NEWLINE { raw_line } 'end'` with a note that `ident` must be a `#[block]` function of an imported package. The note on attributes lists `derive`, `generated` and `block` as compiler-recognised.

## Risks / Trade-offs

- **Build latency**: a cold comptime batch compiles and starts a process. Mitigation: one process per batch (all generator calls of a build in one run), the cache, and tool-free output from `add-direct-pe-output`; documented numbers in the docs.
- **Subset check false negatives or positives** through function values and interface calls. Mitigation: conservative (reject if a call target cannot be resolved statically), plus the sandbox properties of the child (no inherited handles, timeout, memory limit), so a gap in the check is not a gap in containment. Note that a native child running as the user is not a hard sandbox against code that bypasses the check; the check is the security boundary and has tests for each rejected construct, including through helpers and closures.
- **Parser pre-scan** ties parsing to package lookup. Mitigation: lookup failure is not an error, it only means no blocks; tests cover both.
- **Cache key must include everything**: a missing input gives stale code. Mitigation: the key hashes the normalized transitive source and the serialized input; tests change each part in turn.
- **Generated text hard to debug**. Mitigation: `--comptime-dump`, source-mapped errors showing the generated line.
- **Output sizes** can blow up compile time. Mitigation: 1 MiB cap per call, 8 rounds, and the timeout.
- **`Type` API frozen early** is hard to extend. Mitigation: it is small and additive; each new query is a method plus an input line, and the wire format ignores unknown line kinds.
