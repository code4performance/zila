## Notes (decisions taken while implementing)

- **Reflection had not landed** (`add-comptime-reflection` is still an open change). As the design's risk section allows, the compiler expands the derivation itself, with the same behavior: for each type it writes the Zila Lang source of `eq`/`compare`/`hash` (`src/derive_ops.rs`, `derive_source`), parses it, binds the type to the name `__T` and queues it like any generic-record method (memoized in `methods`, so recursive types work). The pieces it is made of are the intrinsics `__eq`, `__cmp`, `__hash`, `__tag`, `__payload` and `__mix`. `std/derive.br` therefore holds only `hash_combine` (for hand-written `hash`); the comptime `derive_eq<T>`, `derive_compare<T>` and `derive_hash<T>` of task 2.2 are not written and can replace the expansion later without changing behavior. `add-int-long-aliases` is archived: `long` is the 64-bit hash type, as designed.
- **Task 2.1 (old `==`)**: recorded in the header comment of `tests/derive.rs`. Records, lists, maps compared pointers; enums with data were a compile error; optionals are the reference types themselves (`x == nil` is unchanged); pointers, functions, channels compare addresses and keep doing so; floats, text and integers are unchanged.
- **Optionals** are the reference type itself in this compiler (`T?` only exists for reference types), so nil handling lives in the comparison: nil equals nil, is below every value, hashes as 0.
- **`Set<T>` keeps no bound on the record** (`type Set<T>`): a bound would report "float does not satisfy Hash" before the required map key message. The free functions (`empty`, `from_list`, `union`, ...) carry `T: Hash`; `Set<float>` still fails with "float cannot be a map key because it is not Hash".
- **`sorted.map()`/`set()`** order with `a < b`; `list.sort` orders with `compare` (so a NaN goes last), delegating to `sort_by`.
- **Text** now supports `<`, `<=`, `>`, `>=` (byte order, same as `text.compare`), needed for `Ord` generic code. Runtime helpers `rt_dv_text_cmp` and `rt_dv_text_hash` live in `src/runtime_derive.asm`, included only when used.
- **Maps**: flag bits 4 (general keys: hash and equality thunks stored at +56/+64, object grows to 72 bytes) and 8 (heap keys; retained and released like text keys, `test flags, 9`). Text and integer keys take the old paths; the only cost is one extra flag test in `rt_map_hash` and `rt_map_find`. `bool` and payload-free enum keys use the integer path. A record key is copied in when assigned (`m[k] = v` uses `value()`). No separate micro-benchmark was timed; `tests/maps.rs` timings are unchanged and the 100,000 record key test finishes in about a second.
- **Method keys** for built-in types now use the full type name (`method_key` uses `ty_full`), so derived methods of `[]a.P` and `[]b.P` cannot collide.
- **Task 3.5** (interpreter): void, `src/interp.rs` was removed by `remove-interpreter`.
- **Task 4.5 review**: `grep` over `std/`, `os/` and `examples/` found no text keys built to simulate record keys, no `==` on records whose meaning changed, and no hand-written `less` that equals `a < b` other than the ones inside `std/sorted.br` (now `map()`/`set()`); `examples/words.br` keeps its `sort_by` (a two-level order).
- **Tests run** (this machine, VS 2022 toolchain): `abort allocator codegen defer derive docs floats fmt format generics integers lsp maps noalloc optimizer parse pe refs run sets sorted stdlib testrun vscode` plus `cargo test --lib --bins`: all pass. **Not run (user rule: no async or I/O tests)**: `tests/async.rs`, `buffered_io`, `udp`, `dns`, `tls`, `linux`, `os`, `ui`, and `error_kinds` (it uses the file system, sockets and TLS). Their compile is checked (`cargo test --no-run`), the Linux output and the operating system libraries and kernel are checked by generating code in `tests/derive.rs` (`linux_output_for_general_keys_generates`, `the_os_libraries_and_kernel_still_compile`), and a Linux record-key map case was added to `tests/linux.rs` for a run with WSL.
