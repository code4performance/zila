## Context

An `error` is a heap object of 8 bytes holding one reference to its message text. `error("msg")` is compiled inline in `src/codegen_x64.rs` (the `name == "error" && args.len() == 1` case: allocate 8 bytes with drop procedure `rt_drop_error`, store the text), `e.message` is the `Ty::Err if name == "message"` arm of field access, and `rt_drop_error` releases the text. The type is `Ty::Err`; the parser reads `T or error` and `-> error` as a fallible result (`RetType { fallible: true }`). The standard library builds every error from a text: `error(sys.describe(task.last_error(), path))` in `std/fs.br`, `std/net.br`, `std/tls.br` (Linux: `sys.describe(fd, path)` with a negative errno), and literal messages such as `error("end of file")` and `error("the socket is closed")`. `sys.describe(code, what)` lives in `std/sys.br` (Windows `FormatMessageA`) and `std/sys.linux.br` (an errno table).

## Goals / Non-Goals

**Goals**
- One `error` type with a kind, a message and a cause; all current code keeps compiling.
- Kinds that libraries can add without touching the compiler or a shared enum.
- The standard library's common failures have the same kind on Windows and Linux.

**Non-Goals**
- Several error types, `T or E`, or typed errors in signatures. `or error` stays.
- Stack traces or source locations in errors.
- Converting errors implicitly in `try` (no `From`).
- Changing any message text.
- Matching on kinds with `match` patterns: `match` over an open set cannot be exhaustive in a useful way, so tests use `==` and `is`.

## Decisions

1. **Open kinds as namespaced names.** `ErrorKind` is a built-in nominal type whose value is a reference to an interned text `package.Name`. Alternatives: (a) a closed `enum` cannot grow without editing the standard library and forces every library to say `Other`; (b) an enum with an `Other(text)` case loses comparability; (c) plain `text` kinds are open but easy to misspell and collide (`"NotFound"` from two libraries). A namespaced name is open (any package adds its own, the namespace is the package name, so collisions need two packages with the same name, which the package manager of `add-package-manager` already forbids), cheap to compare (interned: pointer equality, falling back to text equality), printable, and stable across versions of a library. It is a distinct type so a message can never be passed as a kind by accident. The `std` namespace is reserved for the standard library: `errors.kind` rejects `std.*` unless it is called from a `std` package, which is checked at compile time by the package the call sits in. `errors.kind(name)` returns `ErrorKind or error` (the name must match `[A-Za-z_][A-Za-z0-9_]*\.[A-Za-z_][A-Za-z0-9_]*`); package-level code writes `let Corrupt = errors.kind("mylib.Corrupt") ?? errors.Other`. Because a literal that is wrong is a bug, a later change can add a compile-time form; this change keeps one function.
2. **Standard kinds live in `std/errors.br`** (`package errors`) as package-level `let` values, in the same way `std/fs.br` has `let CHUNK = 65536`, built through an internal `errors.__std(name)` that skips the reserved-namespace check. The list is deliberately short and operating-system neutral (no `EBUSY`, no `ERROR_SHARING_VIOLATION`): `NotFound`, `PermissionDenied`, `AlreadyExists`, `Timeout`, `ConnectionRefused`, `ConnectionReset`, `AddrInUse`, `InvalidInput`, `UnexpectedEof`, `Closed`, `Cancelled`, `Unsupported`, `Io`, `Other`. `Io` is the fallback for an operating-system failure with no mapping, so a caller can always tell "the system said no" from "the library said no" (`Other`). Names can be added later without breaking anyone because kinds are open.
3. **Object layout.** The error object grows from 8 to 24 bytes: `[message: text][kind: text][cause: error or 0]`. `error("msg")` stores the interned `std.Other` (loaded from the `errors` constant, or a runtime-owned static so programs that do not `use errors` still work; the compiler emits one static text `std.Other` and every `errors.Other` is that same object). `rt_drop_error` releases message, kind and, if non-zero, the cause. Releasing the cause through `rt_release` means a chain is freed iteratively by the existing release path; very deep chains (thousands) are not expected and are not special-cased. `e.message` and the new `e.kind` and `e.cause` retain the loaded reference like the existing `message` arm does; `e.cause` has type `error?` and is nil when the word is 0, using the same representation as other optional references.
4. **Constructors are compiler built-ins** like `error` is today, extending the call case in `src/codegen_x64.rs`: one argument (text) is kind `Other`; two arguments (`ErrorKind`, text); three (`ErrorKind`, text, error). The argument types are checked with the existing `self.check`, with a message that mentions `errors.kind(...)` when a text is given where a kind is expected. `e.context(msg)` is compiled as the three-argument form with the kind loaded from `e`; `e.is(kind)` is a small runtime loop `rt_error_is` walking the cause chain comparing kind objects (pointer equality first, then text equality, because a kind built at run time with `errors.kind` is interned by `rt_kind_intern` into a table so equal names share one object: interning makes `==` a pointer comparison and is what lets `ErrorKind` be used as a map key text later). `e.full_message` is a runtime helper that joins the messages with `: `.
5. **`try` converts nothing.** `try` already returns the failure object it received; it keeps doing so. Decision: no implicit conversion, no wrapping, no added context. Rationale: with one `error` type there is nothing to convert to; automatic context would hide the original message; explicit `context` costs one call where it matters. The consequence is that a kind chosen deep in the library reaches the top unchanged, which is what makes `e.kind == errors.NotFound` reliable.
6. **Kinds from the operating system.** A function `sys.error_for(code: int, what: text) -> error` next to `describe` in `std/sys.br` and `std/sys.linux.br` builds `error(kind_of(code), describe(code, what))`, so messages are exactly as before. `kind_of` is a table: Windows 2, 3 (file/path not found), 1168 (not found), 11001 and 11004 (host not found) -> `NotFound`; 5, 1314 -> `PermissionDenied`; 80, 183 -> `AlreadyExists`; 38 -> `UnexpectedEof`; 995, 1223, 125 (cancelled) -> `Cancelled`; 10060, 258, 1460 -> `Timeout`; 10061 -> `ConnectionRefused`; 10053, 10054, 64, 1236 -> `ConnectionReset`; 10048 -> `AddrInUse`; 87, 10022, 10049 -> `InvalidInput`; everything else -> `Io`. Linux errno: ENOENT 2 -> `NotFound`; EACCES 13, EPERM 1 -> `PermissionDenied`; EEXIST 17 -> `AlreadyExists`; ETIMEDOUT 110 -> `Timeout`; ECONNREFUSED 111 -> `ConnectionRefused`; ECONNRESET 104, ECONNABORTED 103, EPIPE 32 -> `ConnectionReset`; EADDRINUSE 98 -> `AddrInUse`; EINVAL 22 -> `InvalidInput`; ECANCELED 125 -> `Cancelled`; ENOSYS 38 -> `Unsupported`; else `Io`. Call sites `error(sys.describe(code, what))` become `sys.error_for(code, what)`. Library-made errors name their kind directly: `error(errors.UnexpectedEof, "end of file")`, `error(errors.Closed, "the socket is closed")`, `error(errors.InvalidInput, ...)` in the parsers, `error(errors.Unsupported, "TLS: renegotiation is not supported")`, TLS handshake and decrypt failures `Io` through `error_for` (SSPI codes land in the fallback), `error(errors.NotFound, "cannot resolve '{host}'")`. `std/task.br` has no `error(...)` call today; its part is to confirm that `last_error()` and the status mapping (`op.status` with 995 for a cancelled operation and the timer paths) stay the single source of codes for `error_for`, and to give `Cancelled`/`Timeout` where a task-level failure is produced (checked in task 4.4; if there is none, the task records that and changes nothing there).
7. **Interpreter and OS.** The `--run` interpreter (`src/interp.rs`, `Value::Error(m)`) is not extended: `remove-interpreter` deletes it. If this change lands first, the interpreter keeps the old one-field error and `kind` is a compile error there (`tests/` that use it are listed in task 3.3). `os/*.br` (the kernel) does not use `error`; verified in task 6.3.
8. **Compatibility and size.** Every existing program compiles unchanged. Errors cost 16 more bytes and two more releases. `error("msg")` is no slower, because the kind is one static pointer.

## Risks / Trade-offs

- Interned kinds need a small runtime table; it is only touched by `errors.kind`, not by the standard kinds, which are constants created at startup. A program that creates kinds from user input in a loop grows the table; documented ("make kinds once, at package level").
- Open kinds mean `match` cannot be exhaustive over them; the documentation shows `if e.kind == ...` chains and `is`.
- The `std` namespace guard is per package at compile time, not a security boundary.
- Mapping tables are judgment calls (for example 87 `ERROR_INVALID_PARAMETER` -> `InvalidInput`); anything not listed is `Io`, which is always correct but coarse, and the table can grow.

## Depends on

- `add-direct-pe-output`: independent; if it lands first nothing changes here (the runtime assembly in `src/codegen_x64.rs` is the same text either way, so the new helpers `rt_error_is`, `rt_kind_intern`, `rt_error_full` are added to the same runtime section).
- `remove-interpreter`: removes the `src/interp.rs` error value; see decision 7. Prefer landing it first, then task 3.3 disappears.
- `add-visibility-pub`: the standard kinds and `errors.kind` must be `pub` once visibility exists; this change writes `std/errors.br` with the declarations that change will mark `pub`.
- `remove-panic-add-abort`: the reserved-namespace and name-format violations are errors, not panics; no overlap.
- `remove-async-coloring`: the standard library rewrites in tasks 4.x edit the same signatures (`async func`); whichever lands second rebases. Error kinds are independent of coloring.
- `add-package-manager`: supplies the package-name uniqueness that makes `package.Name` kinds collision-free; until then names are only unique by convention.
- `add-text-bytes-and-char`: the kind name and the `parse_*` messages are `text`; if text becomes validated UTF-8, kind names are ASCII by the format rule and are unaffected.
- `add-derived-eq-ord-hash`: `ErrorKind` has built-in equality; `add-derived-eq-ord-hash` may later derive equality for records containing a kind.
- `add-json`, `add-web`, `add-threads-and-shared`: consumers; they should define their kinds with `errors.kind` (for example `json.Syntax`, `web.BadRequest`) and a thread-shared error needs the kind table to be thread-safe (interning is behind the `add-threads-and-shared` synchronization if it lands; until then the runtime is single-threaded).
- `add-weak-refs`, `add-copy-on-write`, `restrict-ref-escape`, `add-comptime-reflection`, `add-int-long-aliases`, `add-no-alloc-and-allocator`: no dependency. Under `add-no-alloc-and-allocator` an error allocation is an allocation that a no-alloc function cannot do; kind constants are static and fine.
- `add-error-kind` is the owner of the error object layout; other changes must not add fields to it.

## As built (differences from the plan above)

- **`error?` is the type of an error value.** `-> error` in a signature already means "fails or not" (a fallible function that returns nothing), so a function that *returns* an error object (`sys.error_for`, `future.timed_out`) is declared `-> error?`. `error` became a nullable type (`Ty::Err` is nullable), which is also what makes `e.cause` (`error?`) and `e.cause == nil` work; the "cannot compare a result" check lets `nil` through. Callers write `return sys.error_for(code, what)` unchanged.
- **Reserved `std` namespace.** The compiler has a hidden built-in `__kind(name)` (the interning call); `errors.kind` rejects `std.*` always (it cannot know its caller) and the standard library builds its kinds with `errors.__std(name)` / `__kind`. So the rule is per function, not per calling package. Once `add-visibility-pub` lands, `__std` should be package-private.
- **`std.Other` is a static node.** The kind table (`rt_kinds`) is a linked list of `[next][text]` nodes whose first node is static data holding `std.Other`; `error("msg")` therefore costs no allocation and `live_objects()` is unchanged for programs that never make a kind (the bare-metal shell test counts live objects). Other kinds add one 16-byte node each on first use; lookups are a list walk (kinds are made once, at package level).
- **Mapping tables grew** (all still "else `Io`"): Windows 1225 (`ERROR_CONNECTION_REFUSED`, what an overlapped `ConnectEx` reports) -> `ConnectionRefused`, 1227 -> `AddrInUse`, 121 -> `Timeout`, 10040 and 1784 (oversized datagram on send) -> `InvalidInput`, 10051/10065/1231/1232 -> `Unavailable`; Linux 90 (`EMSGSIZE`) -> `InvalidInput`, 101/113 -> `Unavailable`. `sys.kind_of` on Linux accepts a negative result of `syscall` as is.
- **`timeout(ms, f)`** fails with kind `Timeout` (the compiler's template calls `future.timed_out()`); the message `timed out` is unchanged. This is the task-level failure of task 4.4 (`std/task*.br` themselves have no `error(...)`).
- **`sorted`** lookups with no result (`min`, `max`, no key at or below/above) are `NotFound` (added to the table in the spec).
- **Not applicable / unchanged:** the language server lists no members, so there was nothing to extend (task 1.6); `src/interp.rs` was already removed by `remove-interpreter` (task 3.3); `std/task*.br` and `std/float.br` contain no `error(` calls.
- Remaining `error("...")` without a kind: none in `std/`; `os/kernel.br` and `examples/defer.br` use `error("...")` (kind `Other`) and compile unchanged.
