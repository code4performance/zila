## Context

`add-linux-target` produced a static ELF with `write`, `exit_group`, `mmap` and `munmap`. The libraries that are rejected there are written in Brasa on top of Windows imports declared with `extern "system"` and `#[link]`: `std/task.br` (fibers, a completion port, timers), `std/fs.br` (overlapped file I/O), `std/net.br` and `std/ws.br` (Winsock, `GetAddrInfoExW`), `std/sys.br` (`FormatMessageA`), `std/ui.br` (Win32). Channels, futures, `bufio` and `format` are platform neutral and sit on `park`, `wake`, `add_timer` and `op_wait`. The compiler lowers `spawn`, `send`, `receive` and `async` to functions of `task` and `future`.

## Goals / Non-Goals

**Goals**
- One source builds for both targets with the same behavior (see the spec for the few text and machine-dependent differences).
- Keep the property that a Linux program needs no tool and no library, except when it declares `extern`.

**Non-Goals**
- `ui` (a window toolkit). The options are an X11 or Wayland client written in Brasa over the display socket, or a GTK binding through `extern` once calling C works; each is a project of its own and should be decided separately.
- Multiple threads, `io_uring`, signals, processes, environment and arguments, macOS, other architectures.

## Decisions

1. **Library selection by target, not conditional compilation.** `load` resolves `std/<name>.linux.br` before `std/<name>.br` when the target is Linux. A `.linux.br` file declares the same package, types and functions as the Windows file. This needs no new syntax, keeps each file readable, and a test checks that both files export the same names and signatures (a comparison of the declarations after parsing). Shared logic moves out of the platform file into the neutral one only where it is already neutral (the `Reader` and `Writer` code in `net.br` and `fs.br` is the main candidate; moving it is optional and done only if it reduces duplication).
2. **Order of work follows the dependencies:** division check → fibers and time → scheduler with `epoll` → `fs` → sockets → name lookup → errors text → `extern`. `sys` and the division check come first because later steps use them for messages.
3. **Fibers.** A task owns a stack from `mmap` (256 KiB with a guard page at the low end, released with `munmap` when the task is reaped; stacks of finished tasks are cached up to a small limit so spawning is cheap). The context switch is a short routine in the Linux runtime: push `rbx`, `rbp`, `r12`–`r15`, store `rsp` in the old context, load the new one, pop, `ret`. `task.br`'s Linux layer exposes the same four operations the Windows layer uses (`ConvertThreadToFiber`, `CreateFiber`, `SwitchToFiber`, `DeleteFiber`) under runtime names, so the scheduler logic is unchanged. A first switch into a new fiber lands in a trampoline that calls the entry function with its argument and never returns (the scheduler reaps it).
4. **Time and waiting.** `now()` uses `clock_gettime(CLOCK_MONOTONIC)` (228) converted to milliseconds. Waiting for I/O and timers is `epoll_wait` (232) with the time to the next timer as its timeout (−1 with no timer; a deadlock is still detected as today when there is neither a timer nor a registered descriptor with a waiting task).
5. **Readiness, not completion.** Windows reports finished operations; Linux reports readiness. The Linux layer therefore keeps the Windows-facing shape of `op_new` / `op_submit` / `op_wait` for the shared code but implements an operation as "try the system call; on `EAGAIN` register the descriptor with `epoll` (edge-triggered, one-shot per wait) and park; when readiness arrives, wake the task and retry". Sockets are created non-blocking (`SOCK_NONBLOCK`, `accept4`).
6. **Regular files.** `epoll` does not accept regular files and reads from them do not return `EAGAIN`. File reads and writes are done synchronously in chunks of at most 64 KiB with a `yield` between chunks, which gives the spec's bound without threads. (This is the honest limitation; a thread pool or `io_uring` can replace it later behind the same API.)
7. **Name lookup in Brasa.** There is no libc, so the resolver is part of `net.linux.br`: read `/etc/hosts` (and answer `localhost`), parse IPv4 and IPv6 literals, read the `nameserver` lines of `/etc/resolv.conf` (default `127.0.0.1`), send an `A` query over a UDP socket with a 2-second timeout and up to two tries per server, parse the answer (follow compression pointers and `CNAME` chains), fall back to TCP when the truncation bit is set. The query runs in the calling task over the non-blocking UDP socket, so other tasks are never stopped. It reuses the UDP code of `net`.
8. **Error text.** `sys.linux.br` holds a table of the standard `errno` messages (about 130 entries) and negates the kernel's `-errno` return values; `fs` and `net` build `path: reason` strings from it. Messages are compared only up to the path prefix in cross-platform tests.
9. **Calling C.** A program with no `extern` stays static, so nothing changes for it. With externs the compiler writes a dynamic executable: `PT_INTERP` (`/lib64/ld-linux-x86-64.so.2`), `PT_DYNAMIC` with `DT_NEEDED` for each `#[link("x")]` (`libx.so.6`/`.so` names from a small table, `c` → `libc.so.6`, `m` → `libm.so.6`, others → `lib<name>.so`), `DT_SYMTAB`, `DT_STRTAB`, `DT_HASH` (or `DT_GNU_HASH`) and `DT_RELA` with `R_X86_64_GLOB_DAT` entries into a table of pointers that the generated code calls through (`call qword ptr [rip + slot]`), with `DT_BIND_NOW`. The loader sets the stack and calls `brasa_start`; because libc initializes itself before our entry only when it is the main program, the entry keeps its own start-up and the C library works for stateless functions; what C buffers is flushed because the program leaves through the C library's `exit` (a program with externs imports it automatically); the C library was checked on glibc under WSL (musl was not tried), and the runtime calls `fflush(NULL)` before each write, so what C printed keeps its order with what Brasa prints. The calls translate Brasa's argument registers (`rcx`, `rdx`, `r8`, `r9` plus stack) to System V (`rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9` plus stack) in a per-extern thunk, saving the Brasa-reserved registers. Callbacks (`extern "C" func(...)` arguments) get a reverse thunk (`CB_<name>`) that moves up to six System V arguments (integers, pointers, floats) to the Brasa registers and a float result to xmm0; the call site itself is a System V call through the import slot, no per-extern thunk is needed.
10. **Division check.** The generated code compares the divisor with zero before `idiv` and calls `rt_panic("division by zero")`. Constant folding is unchanged (a zero divisor is never folded); the check is two instructions and is left out when the divisor is a non-zero literal. It applies to the Windows and Linux targets; the bare-metal kernel keeps its current behavior (the image must stay identical, and the kernel handles faults itself).
11. **Testing.** Cross-platform programs live in `tests/programs/` (or the examples folder): each is built for both targets, run (Windows natively, Linux under WSL) and the outputs compared. Per-library tests cover the rest: `epoll` readiness with sockets on the loopback, a large file round trip, ten thousand tasks, a deadlock, an echo server, a UDP exchange, lookups of `localhost`, a literal and an `.invalid` name (tests that need a real DNS server are skipped when none answers), an `extern` call into libc, and a check that a program without externs has no `PT_INTERP`. The suites `async`, `net`, `fs`, `udp`, `dns` run on both targets; when WSL is unavailable the Linux half is skipped with a message.

## Risks / Trade-offs

- `extern` through the dynamic loader is the largest piece; it can be split into its own change if the rest lands first. The design keeps it last for that reason.
- Regular-file I/O is synchronous per chunk, so a very slow disk can delay other tasks by one chunk.
- DNS over UDP in Brasa covers `A` records (and `AAAA` if the Windows API returns IPv6 today; check against `net.lookup`'s result type) but not DNSSEC, EDNS or search-domain expansion; behavior with unusual resolver setups (systemd-resolved stub at `127.0.0.53`) works because it is an ordinary UDP server.
- Adding the division check changes the Windows machine code: the performance suites compare against `--no-opt` outputs, not code size, but the inlining benchmark is rerun to confirm the loss is small.
- Error wording differs between platforms by design; programs should not parse it.
