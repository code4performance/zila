## Context

Today: `std/task.br` (Windows fibers) and `std/task.linux.br` (mmap stacks, `epoll`) keep the whole scheduler in module-level `var`s (`tasks`, `ready`, `current`, timers, I/O port or `epfd`). The runtime in `src/codegen_x64.rs` (`RUNTIME_COMMON`: `rt_retain` is `inc qword ptr [rcx-16]`, `rt_release`; per-target `rt_alloc`/`rt_free_obj` with size-class free lists and a bump pointer; `rt_live` is a plain counter, read by `live_objects()`) assumes one thread. `StmtKind::Spawn` is lowered to `task.start(func() f(x) end)`. A Windows executable is built from generated assembly (the direct PE writer is `add-direct-pe-output`); Linux static executables use raw system calls and no libc.

## Goals / Non-Goals

**Goals**
- Real OS threads with data-race freedom by construction, decided by the compiler from types, with no user annotation.
- Zero cost for programs that do not use threads.

**Non-Goals (stage 2, later change)**
- A work-stealing parallel scheduler that migrates tasks between threads, parallel `async` (futures completing on a thread other than the creator), thread pools in the standard library, thread-local storage as a user feature, scoped threads that borrow, condition variables and read-write locks (a `Mutex` plus a channel covers the first use cases; they can be added later without changing these rules).

**Depends on**: `add-weak-refs` (the `new T` reference kind and weak counts that `shared` mirrors), `add-copy-on-write` (counts and write-copies of values), `add-derived-eq-ord-hash` (identity versus value comparison on `shared`), `remove-async-coloring` (async/await and `spawn` semantics that the per-thread scheduler keeps), `add-direct-pe-output` (the Windows `CreateThread` and TLS support must be assembled by the built-in assembler; no `ml64`). Related but not dependent: `add-error-kind`, `remove-panic-add-abort` (a panic in a thread aborts the process), `restrict-ref-escape`, `add-no-alloc-and-allocator` (a custom allocator must itself be thread safe or be per thread), `add-visibility-pub`, `remove-interpreter` (threads exist only in compiled code; the interpreter, if still present, rejects `spawn_thread`).

## Decisions

1. **Two reference kinds, as Rust `Rc`/`Arc`.** `new T` keeps non-atomic counts. `shared T` uses `lock inc`/`lock dec` (`rt_retain_atomic`, `rt_release_atomic`, with the same `[refcount][drop][payload]` header so `rt_free_obj` and drop procedures are shared). The compiler picks the procedure from the static type, so there is no per-object flag test on the fast path. A `shared T` handle copied out of an object is retained atomically; the objects inside a `shared` (list elements, text) are plain values whose counts are touched only by the thread that owns a private copy (see 7).
2. **Transferable is a computed property, not an annotation.** A function `transferable(type) -> Result<(), Path>` in the type checker walks the type structurally, with memoization and a cycle guard (recursive types assume "yes" while visiting). It returns the first offending path (`job.owner.next`) and type, which is what the error prints. Closures: captures are already known to the checker (used by `spawn` and `defer`). Function values that are not closures (top-level functions) are transferable. `unsafe` blocks and raw pointers (`*T`, `usize` handles) are NOT checked inside, but a record holding a raw pointer type is not transferable, so FFI handles cannot cross by accident; `unsafe` code may wrap one in a type declared transferable only through `shared`.
3. **`shared` is immutable by default; mutation uses `Mutex<T>` or `Atomic`.** Decision and why: (a) immutability makes plain reads race-free with no cost and matches `Arc<T>` plus `Mutex<T>`; (b) a mutable-by-default `shared` would need a lock on every field access or would permit data races, which this design forbids; (c) an explicit `Mutex<T>` makes the cost visible in the code. `m.lock()` returns a guard released with `defer`; the guard borrows nothing that can escape (it relies on `restrict-ref-escape`; until that lands, `lock` takes a closure `m.with(func(ref v: T) ... end)` as the only API, which cannot leak the reference, and the guard form is added with it). `Atomic` covers the most common case (counters, flags) without locking. A `shared T` where `T` contains `new` is rejected, since `shared T` would not be transferable.
4. **`Mutex` implementation.** A futex-like word: on Linux the `futex` system call (202) through `sys`; on Windows `WaitOnAddress`/`WakeByAddressSingle` from `api-ms-win-core-synch-l1-2-0` (or `kernel32` forwarders). Spin a few iterations, then sleep. No re-entrancy (the owner thread id is stored and compared, giving the clear error of the spec). Poisoning is not supported: a panic aborts the process.
5. **`spawn_thread` lowering.** The parser adds `spawn_thread` (a statement and an expression yielding `Thread`) next to `Spawn`. The call is lowered to `thread.start(func() f(args) end)` after `args` are evaluated and retained on the caller (arguments are moved into the closure; transferable values carry no `new` references, so no non-atomic count is shared). The closure object itself is transferred: its count is set to 1 and owned by the new thread, which releases it when `f` returns. If the closure holds copy-on-write values, their counts use the atomic procedures (7).
6. **OS threads without libc.**
   - Windows: `CreateThread` (kernel32), `WaitForSingleObject` for join, `ExitProcess` for panics. The thread start routine is an assembly stub `zila_thread_entry` that sets up the per-thread block, then calls the Zila Lang closure. A TLS slot (`TlsAlloc` at startup, or the `gs:` segment through the TEB: `TlsGetValue` is used first for simplicity) holds the per-thread block pointer.
   - Linux: `mmap` the thread stack (as `std/task.linux.br` already does, with a guard page), `clone` with `CLONE_VM|CLONE_FS|CLONE_FILES|CLONE_SIGHAND|CLONE_THREAD|CLONE_SYSVSEM|CLONE_SETTLS|CLONE_PARENT_SETTID|CLONE_CHILD_CLEARTID`, the TLS base set with `arch_prctl`-style `CLONE_SETTLS` pointing at the per-thread block (`fs:`-relative access), and join with `futex(FUTEX_WAIT)` on the child-tid word that the kernel clears and wakes at thread exit. The child's first instructions are an assembly stub (the new stack is prepared by the parent: return address and closure pointer on it) that cannot use the parent stack. Thread exit is `exit` (60), not `exit_group`; process exit is `exit_group`.
   - `thread.start` is the only place with this assembly; both layers expose `start`, `join`, `id` and `sleep` with the same signatures, as `task.br` and `task.linux.br` do.
7. **Allocator and counts.**
   - Per-thread block: the thread block (TLS) holds small-object free lists and the bump chunk, so `rt_alloc` and `rt_free_obj` on the fast path touch no shared memory. Each thread takes 64 KiB chunks from the global bump region with a `lock xadd` on `rt_brk` (Linux and Windows use the existing region logic: the 256 MiB zeroed region on Linux, `HeapAlloc`-style chunks on Windows). A block freed by a thread other than its allocator goes to the freeing thread's list (memory migrates between threads; this is simple and bounded for stage 1). Large blocks (`mmap`/`VirtualAlloc`) are independent and need no locking. When a thread ends, its free lists are pushed onto a global lock-protected list that new threads draw from.
   - `rt_live`: `lock inc/dec` is too slow for the single-thread default, so the counter is per-thread in the thread block and `live_objects()` sums the live thread blocks (a registry list guarded by a spinlock) plus a global `rt_live_dead` fed by exiting threads. The sum is exact when other threads are joined, and approximate otherwise, which the spec allows ("exact when joined"). Single-thread programs keep a plain counter in the same block.
   - Copy-on-write: add-copy-on-write decides to copy a value at write time when its count is greater than one. For a value that can be reached from another thread, the count operations and the "count > 1" test use the atomic procedures. The compiler already knows statically which copy-on-write values may become shared: a value of a transferable type that flows into a `shared`, a cross-thread channel `send`, or a `spawn_thread` argument is marked by a one-time `rt_make_atomic` call on the value (it sets a flag bit in the count word; the bit is checked by `rt_retain`/`rt_release` and write checks, costing one test on the non-shared fast path only when the program uses threads at all). When the program has no `shared` or `spawn_thread`, the compiler emits the plain procedures and omits the test entirely. A value marked atomic stays atomic for its life, so a later thread-local use is merely a little slower, never wrong. The write-copy gives a private, non-atomic result.
8. **Per-thread scheduler.** The scheduler variables in `task.br`/`task.linux.br` move into a `Sched` record reached through the thread block (TLS), so existing function names (`park`, `wake`, `yield`, `add_timer`, `start`) keep their signatures and are modified only to read `sched()` instead of module globals. `current` task ids are per thread. A task never changes thread. `main`'s scheduler is the first thread's. Windows: each thread calls `ConvertThreadToFiber` once at start, and has its own completion port (`CreateIoCompletionPort`) so file/TCP completions wake that thread. Linux: each thread has its own `epoll` instance and an `eventfd` used as its wakeup.
9. **Cross-thread wakeups.** A task parked on a channel or a `Thread.join` is identified by `(thread, task id, generation)`. `wake_remote(thread, id, gen)` pushes a node on the target thread's lock-free inbox (a Treiber stack in its `Sched`, `lock cmpxchg`), then rings its doorbell: Windows `PostQueuedCompletionStatus` on its port, Linux a `write` to its `eventfd`. The scheduler's `wait_events` (already the single idle point) drains the inbox and moves tasks to `ready`. The generation check discards a wake for a task that already timed out (as `TIMED_OUT` does for local timers).
10. **Thread-safe channel.** The existing `Chan` record is kept for single-thread use. A channel whose static type may cross a thread (it is passed to `spawn_thread`, captured, or stored in a `shared`) is created as an `SChan`: the same queue plus a spinlock word (a ticket lock protecting `items`/`waiting`), taken for the short critical sections of `send`, `receive` and `close`; waiters are recorded as `(thread, id, gen)`; wakeups use decision 9. The compiler chooses the variant by the type, so `channel(T)` has one syntax and the user sees one type. A `send` moves its transferable value into the queue; the channel's element type is checked at the `spawn_thread` call with the same path error.
11. **Blocking.** There is no thread pool and no hidden offloading: a blocking call blocks its OS thread, which is the point of having threads (move blocking work to a `spawn_thread`). The idle scheduler of a thread blocks in the kernel (`epoll_wait` or `GetQueuedCompletionStatusEx`) with the next timer as timeout, so an idle thread uses no CPU. Deadlock detection (stage 1): a thread reports a deadlock only if it has no ready task, no timer, no I/O and the process has no other thread that could post to it; with other live threads it sleeps. A global live-thread count, in an atomic, supports this; if all threads are idle and parked, the last one to park reports the deadlock for the program.
12. **Mutable globals.** The checker builds the call graph from the function passed to `spawn_thread` (functions are statically known; calls through function values are conservatively assumed to reach every transferable-closure target of that type, and calls through interfaces every implementation) and rejects any access to a global `var` whose type is not `shared`/`Mutex`/`Atomic`. Global `let` of transferable type is fine (constant data). Module initializers run before `main` and before any thread starts.
13. **`live_objects` and the tests of leaks.** See decision 7. The existing leak tests for single threads stay exact.
14. **Targets.** Both Windows and Linux. The bare-metal kernel (`os/`) rejects `spawn_thread`, `shared` allocation falls back to non-atomic procedures there, since the kernel is single threaded.
15. **Staging.** Stage 1 (this change) ends with everything above. Stage 2 (not planned here): a worker pool scheduler where tasks may run on any worker; it would need tasks to be transferable, which the computed property already supports.

## Risks / Trade-offs

- Per-thread free lists leak memory between threads in producer/consumer patterns (producer allocates, consumer frees). Stage 1 accepts this; a periodic return of surplus blocks to the global list is the known fix.
- `clone` and TLS by hand is delicate (stack alignment, signal handling, no libc cleanup). The tests include stress runs (many short threads) under WSL.
- Per-thread `rt_live` makes `live_objects()` approximate while threads run.
- The "atomic flag in the count word" costs a test per count operation in programs that use threads. A cheaper alternative (distinct types in the generated code only) is limited by values flowing through generics and interfaces, so the flag is the safe default. Programs without threads pay nothing.
- The call-graph check for mutable globals is conservative and can reject programs that would be safe; the error names the global and the call path so the user can use `shared`.
- `Mutex` closure-style API is less convenient than guards until `restrict-ref-escape` lands.
