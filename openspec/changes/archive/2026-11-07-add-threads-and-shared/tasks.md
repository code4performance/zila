## Implementation notes

- `shared T` is the same runtime value as `T` with atomic counts: the compiler tracks which bindings hold a shared value (`let s = shared e`, a parameter or `let` typed `shared T`, or a copy of one) and rejects writes through them (assignment, `push`, `add`, `clear`, `take`, `remove`, `insert`, `pop`). A copy that loses the binding (passing it to a function parameter typed `T`) is not tracked.
- Counts: the design chose per-type atomic procedures and a per-value flag. The implementation is simpler: when a program contains `shared`, `spawn_thread` or imports `thread`, the runtime's `inc/dec [rcx-16]` and `rt_live` get `lock` prefixes (assembler text pass `lock_counts`); other programs are byte-identical to before. Atomic counts everywhere make copy-on-write checks across threads correct.
- Allocator: the Windows runtime already allocates with the process heap, which is thread safe, so there are no per-thread free lists; `live_objects()` is exact after joins. The first `spawn_thread` allocates two tables (1024 scheduler places, 256 pending slots), which shows in `live_objects()` once.
- Scheduler: `Sched` per thread, found through a Windows TLS slot (`TlsAlloc`); main uses it only after the first thread starts. Each thread has a completion port as its doorbell; `wake_remote` pushes on the target's inbox (spin lock) and posts to the port. A channel waiter is recorded as `slot * 2^32 + task id`.
- Deadlock: a global count of live threads and of threads that only another thread can wake (an idle scheduler with no timer, a `join`); when they are equal the program stops with `fatal: all tasks are asleep - deadlock!`.
- Reconciled with `add-weak-refs`: `new T` is `Rc<T>`, shown as `new T` in errors, and `Rc<T>`/`Weak<T>` are never transferable. A type is written `Rc<Node>` (alias it to use it in `channel(...)`).
- `thread.start` lowers `spawn_thread f(a, b)` after evaluating non-trivial arguments into hidden locals on the calling thread; closures passed as arguments are checked for captured variables.
- A `Mutex<T>` API without guards: `update(func(v) ... end)`, `with`, `get`, `set`, and `lock`/`unlock` with `locked_get`/`locked_set` (the guard form waits for `restrict-ref-escape`).
- Not run (user rule): `tests/async.rs` and the I/O suites (`buffered_io`, `udp`, `dns`, `tls`, `linux`, `os`, `ui`, `error_kinds`); they all compile (`cargo test --no-run`).
