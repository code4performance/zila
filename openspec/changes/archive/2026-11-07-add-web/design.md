## Context

`std/net.br` offers `connect`, `listen`, `Listener.accept`, `Conn.read(max)`, `Conn.write(data)` and a buffered `Reader` (`read_line`, `read`, `read_all`) over `bufio.InBuf`; the scheduler in `std/task.br` provides `task.start`, timers (`add_timer`), `park`/`wake`, and `spawn f(x)`. `std/tls.br` offers `tls.connect(host, port)` with `read`/`write`. `examples/types.br` already declares `Handler` and `Middleware`, and `examples/rest_api.br` shows `app.get`, `req.param`, `http.json`, `http.created`.

The library is plain Zila Lang: nothing in it needs a new compiler feature except the templating entry point, which uses the generic block form of `add-comptime-reflection`.

## Depends on

All four changes this one was written against have landed (they are archived and their specs are in `openspec/specs`):

- `comptime-reflection`: `html ... end` blocks are handed to a `#[block] comptime func` as raw text and it returns code; `#[generated]` functions give `web.read_json`, `web.json` and `web.created` their per-type code.
- `json-library`: `json.parse` and `json.encode` do the work; `web` adds no JSON code of its own (it uses `json.stringify` for the `{"error": ...}` body).
- `error-kinds`: errors carry a kind (`errors.NotFound`, `errors.InvalidInput`, `errors.Timeout`, ...); `web` maps kinds to statuses and defines one kind of its own, `web.UnsupportedMedia`.
- `remove-async-coloring`: the library is plain `func`s with `await` at each wait point (`async` is only used by `net`, `tls` and the tests); `await` is allowed anywhere.

Language facts the design had to follow (the artifacts predate them): the library is a package with `pub` on everything users touch (`Request`, `Response`, `Server` and their fields, the helpers named below), private helpers are unmarked; sizes are `int`, times and ports `long`; `use` of an unknown name is a compile error, so `web` is registered like `json` (`std_source`); a closure captures by value, so state shared by requests lives in a `#[shared]` record or a package-level `var`.

## Goals / Non-Goals

**Goals:**
- The API of `examples/rest_api.br` works, with `web` instead of `http`.
- A server survives 100 concurrent clients on one scheduler, including slow and misbehaving ones.
- The same behavior on Windows and Linux (the library only uses `net`, `tls`, `task`).
- Every interpolated value in a template is escaped unless the author opts out explicitly.

**Non-Goals:**
- HTTP/2, WebSocket, server-side TLS (`tls` is client-only), compression, multipart forms, cookies and sessions (follow-ups), static file serving, a database library.
- Streaming bodies: request and response bodies are whole `text`, bounded by limits.

## Decisions

1. **One task per connection.** `app.run()` loops on `accept()` and does `spawn serve(conn, app)`; the scheduler already multiplexes them, so 100 clients need no extra machinery. A counter `max_connections` (default 1024) makes new connections beyond it receive `503` and close immediately.
2. **Parsing on a `Source`.** The head is read line by line from a `Source` (a `bufio.InBuf` filled from a `net.Conn` or a `tls.Conn`, the same buffer `net.Reader` uses; `net.Reader` itself cannot refuse an over-long line before it has buffered it, and the client needs the TLS variant) up to `max_head` bytes (default 16 KiB for all header lines, 8 KiB for the request line): over the limit gives `431` (or `414` for the request line). The body is read with `Content-Length` (limit `max_body`, default 1 MiB, `413` when over) or `Transfer-Encoding: chunked` (chunk sizes in hex, trailers ignored, the same total limit). Both present at once is `400`. Methods are an enum `Method` (`Get`, `Post`, `Put`, `Delete`, `Patch`, `Head`, `Options`); any other method is `501`. Header names are compared case-insensitively (stored lower-cased in a `Map<text, text>`); a repeated header is joined with `, `.
3. **Keep-alive and timeouts.** HTTP/1.1 connections stay open unless `Connection: close` is sent or received; HTTP/1.0 closes unless `keep-alive` is requested. After a response the task waits for the next request for at most `idle_timeout` (default 5 s); a request that has started must be complete (head and body) within `read_timeout` (default 10 s). Timeouts use `task.add_timer` to call `conn.cancel(...)`, a new plain function of `net` that ends the I/O waiting on the connection without closing it (Windows: `CancelIoEx`; Linux: `shutdown`, so a parked `wait_fd` wakes: closing a descriptor under `epoll` would never wake it), so the task can still write the `408`; a generation counter on the connection makes a stale timer do nothing, so timers need no cancellation. A request that timed out after starting gets `408`; an idle connection is closed silently. Writes have `write_timeout` (default 10 s) the same way.
4. **Records.** `Request { method: Method, version, path, raw_path, query: Map<text,text>, headers, body: text, params: Map<text,text> }` with methods `param(name) -> text?`, `query_param(name) -> text?`, `header(name) -> text?`. `Response { status: int, headers: Map<text,text>, body: text }` built by `web.text(status, s)`, `web.json_text(status, s)`, `web.html_page(status, page)`, `web.not_found()`, `web.redirect(url)` (and the generated `web.json(T, status, value)` and `web.created(T, value)` of decision 8); the JSON ones set `Content-Type: application/json`, the others `text/plain` or `text/html; charset=utf-8`. The server adds `Content-Length` and `Connection`. Percent-decoding applies to path parameters and query values; a bad escape is `400`.
5. **Router.** `app.get/post/put/delete/patch(pattern, handler)`. Patterns are split on `/`; a segment starting with `:` captures one segment, and `*rest` as the last segment captures the remainder. Matching is by method then segments; static segments win over parameters, registration order decides otherwise. No match for the path gives `404`; a match for the path with another method gives `405` with an `Allow` header. `HEAD` falls back to `GET` without a body. Trailing slashes are not significant.
6. **Middleware.** `app.use(m: Middleware)` appends to a chain; the chain is folded once at `run()` into a single `Handler`, outermost first, so `use(a); use(b)` runs `a` before `b`. A middleware may return without calling `next` (short-circuit), change the request, or change the response. Middleware also wraps the 404/405 result, so loggers see every request. One middleware ships: `web.logger()` (method, path, status, milliseconds, to standard output). There is no recover middleware: the language has no panic (`remove-panic-add-abort`), errors are values.
7. **Error mapping.** A handler returns `Response or error`. The server turns an error into a response with `app.on_error(func(err: error) -> Response)`; the default maps by kind: `InvalidInput` 400, `Unauthenticated` 401, `PermissionDenied` 403, `NotFound` 404, `AlreadyExists` 409, `web.UnsupportedMedia` 415, `Unavailable` 503, `Timeout` 504, everything else 500. The body is JSON `{"error": "<message>"}` for 4xx and the fixed text `internal error` for 5xx (the message goes to the log, not to the client: `app.log_to(f)` receives it, `print` by default). Kind names are exactly those `error-kinds` defines.
8. **JSON.** `req.json(T)` as a method is not possible: a comptime type argument cannot be forwarded through an ordinary function, and generated functions are plain functions. So `web.read_json(T, req)`, `web.json(T, status, value)` and `web.created(T, value)` are `#[generated]` functions whose generated body calls `json.parse<T>` / `json.encode<T>` (the explicit type-argument form, so generic types such as `[]Customer` work). That code is compiled in the calling program, which therefore also writes `use json`. `read_json` checks that `Content-Type` contains `json` (else the error kind `web.UnsupportedMedia`, `415`); a parse error is an `InvalidInput` error and so `400`. No JSON code lives in `web`.
9. **Client.** `web.get(url)`, `web.post(url, body)`, `web.post_json(url, text)` and `web.request(method, url, headers, body)` (`web.request_with(opts, ...)` takes a `ClientOptions`) return `ClientResponse { status, headers, body } or error`. `http://` uses `net.connect`, `https://` uses `tls.connect` (certificate and name validated by `tls`; no way to turn that off). Requests are HTTP/1.1 with `Connection: close`, reading until close, `Content-Length` or the last chunk, with `max_response` (default 16 MiB) and a total `timeout` (default 30 s). Redirects (301, 302, 303, 307, 308) are followed up to 5 times, only to `http`/`https` URLs; a redirect from `https` to `http` is an error (the rule is `web.redirect_allowed(from, to)`, which is what the tests exercise: there is no TLS server to redirect from). The total `timeout` starts once the connection (and TLS handshake) is made: connecting is bounded by the operating system. Host names are resolved by `net`. A server speaks plain `http`; TLS termination is left to a proxy until `tls` has a server side.
10. **Templates: `html` blocks.** A block `html ... end` is the generic block form of `comptime-reflection`; the library defines `#[block] comptime func html(raw: text) -> text`. The function parses the raw text at compile time into text runs, `{expr}` interpolations and control lines. Control flow uses lines that start with `@`: `@for u in users`, `@if cond`, `@else`, `@else if cond`, `@end`; `@@` at the start of a line is a literal `@`; this keeps markup free of ambiguity with `<`/`>`. `{{` and `}}` give literal braces. Each non-directive line is trimmed and emitted followed by a newline (the final newline of the whole block is dropped). The generated expression is `web.__page(func(b) ... end)`: a lambda (passed to a function so that it gets its type) that appends to a `#[shared] Builder`, because a lambda cannot be called in place and `return` inside one needs an expected type. Literals go in as they are; each `{expr}` goes through `web.__put(b, expr)`, a generic function bounded by the interface `web.Piece` (`html_piece(self) -> text`), which `text` (escaping), `web.Safe` (unescaped), `int`, `long`, `float`, `bool` and `char` implement, so the escaping is chosen by the static type (a block cannot know it and the language has no overloading). `{raw(expr)}` is rewritten to `web.raw(expr)`, the only way to insert unescaped text, and a `web.Safe` value is what a nested `html` block returns, so templates compose. The block therefore evaluates to a `web.Safe` (field `markup`), not to bare `text`: `web.html_page(status, page)` takes one. Malformed templates (unbalanced `@end`, unclosed `{`, unknown directive) make the generator abort with a message, which the compiler reports as an error at the block's position. `web.escape` replaces `& < > " '` with entities, so values are safe in element text and in quoted attributes; unquoted attributes, `<script>` and `<style>` contents and URLs are not covered and the documentation says so.
11. **Registration.** `std/web.br` is one portable file added to the library tables in `src/codegen_x64.rs` (no Linux layer of its own: `net`, `tls` and `task` have theirs); `use web` is rejected in the bare-metal kernel together with `net`. The only change to the other libraries: `net.Conn.cancel(writes)` and `net.Listener.cancel()` on both layers (`ws.CancelIoEx` on Windows, `shutdown(2)` on Linux), and `task.cur()` on the Linux layer (the Windows one had it).
12. **Tests.** `tests/web.rs` compiles Zila Lang programs that start the server and a client in the same program on 127.0.0.1 with port 0 and runs them with a time limit; nothing reaches the network. The one test that needs the public internet (`https://example.com/`) runs only when `ZILA_ONLINE_TESTS=1`. Pure helpers (`web.escape`, `web.unescape`, `web.redirect_allowed`) are tested through small programs, the router and the parser through the sockets. Each important program also runs on Linux through WSL.
13. **Running servers.** `app.run()` listens and serves until the program ends; `app.start()` serves in a background task and returns a `Running` (`port`, `stop()`), which is what tests and programs that also act as clients need. `web.server(port: 0)` picks a free port.

## Risks

- Whole-body buffering means a large `max_body` costs memory per connection; defaults are conservative.
- Reading the head line by line through `net.Reader` copies; acceptable for a first version.
- Slowloris is bounded by `read_timeout` per request and `max_connections`, not by a rate limit.
- The template directive syntax (`@for`) can change before 1.0; templates are rewritten together with the repository.
- `add-error-kind` and `add-json` names may shift in review; tasks refer to them by role and the final names are taken from the merged changes.
