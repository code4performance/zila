## Notes (decisions taken while implementing; every deviation from the earlier artifacts)

The artifacts of this change predate the int/long aliases, derived `Eq`/`Ord`/`Hash`, copy-on-write, comptime reflection with generated functions, `char`/`bytes`, `Rc`/`Weak`, threads, `pub` visibility, the `json` library and the package manager. The change was reconciled with them as follows.

- **`req.json(T)` and `web.json(status, value)` became `web.read_json(T, req)`, `web.json(T, status, value)` and `web.created(T, value)`.** A comptime `Type` cannot be forwarded through an ordinary function or method (`json.parse(t, ...)` inside `func f(comptime t: Type)` is a compile error), so the three are `#[generated]` functions of the library. Their generated body calls `json.parse<T>` / `json.encode<T>` and is compiled in the calling program, which therefore also writes `use json`. The type is given either as an argument (`web.json(Customer, 200, c)`) or as a type argument for generic types (`web.json<[]Customer>(200, rows)`). `web.json_text(status, text)` takes JSON you already have. `web.created(T, v)` replaces the old `web.created(v)`.
- **`html` yields a `web.Safe`, not `text`.** The generated code cannot know the static type of an interpolated value, and interpolating a record into text is a compile error, so the escaping is chosen by an interface bound: `web.__put<T: web.Piece>` with `html_piece` implemented for `text` (escapes), `web.Safe` (does not), `int`, `long`, `float`, `bool` and `char`. A nested block therefore composes unescaped, as the spec says, and the outer value needs a `markup` field: `web.html_page(status, page)` takes a `Safe`, `web.raw(text)` makes one. Lines are trimmed and joined with newlines. Extras: `@else if cond` and `@@` (a literal `@` at the start of a line).
- **No overloading and no optional enums.** `web.Method` is an enum; `Method?` is not allowed, so `method_of` is split from `is_method`. `web.Get`, `web.Head`, ... are the variants.
- **Timeouts need `cancel`.** Closing a socket under a parked task would never wake it on Linux (`epoll` forgets a closed descriptor), and on Windows would stop the `408` from being written. `net.Conn.cancel(writes: bool)` and `net.Listener.cancel()` were added to both layers of `net` (`CancelIoEx` declared in `std/ws.br`, `shutdown(2)` on Linux) and the timers call them through the generation counter. `Running.stop()` uses `Listener.cancel()`. `task.cur()` was added to `std/task.linux.br` (it existed only on Windows; `std/future.br` calls it) which also fixes the Linux failures that came from its absence.
- **Own line reader instead of `net.Reader`.** `web.Source` is a `bufio.InBuf` filled from a `net.Conn` or a `tls.Conn`: the client needs the TLS variant, and the server must refuse an over-long line before buffering all of it (limits `max_line` 8 KiB and `max_head` 16 KiB).
- **Errors.** Kinds come from the archived `error-kinds` (`errors.NotFound`, ...). Added `web.UnsupportedMedia` (415) for `read_json` and `app.log_to(f)` to receive 5xx messages (`print` by default; there is no stderr in the language). The `{"error": ...}` body is built with `json.stringify`. `web.status_of(err)` and `web.default_error(err)` are public so a custom mapper can reuse them.
- **Server API additions.** `app.start()` returns a `Running` (`port`, `stop()`) and serves in the background; `app.run()` serves until the program ends. Limits are plain public fields (`max_head`, `max_line`, `max_body`, `read_timeout`, `idle_timeout`, `write_timeout`, `max_connections`; milliseconds and bytes). `Request` also has `version` and `raw_path`. Request lines and headers are decoded as UTF-8; a header folded over lines is `400`; `Expect: 100-continue` is answered; leading empty lines before a request line are skipped.
- **Client details.** `web.request(method: web.Method, url, headers, body)` takes a `Method`; `web.request_with(opts, ...)` takes `web.client_options()` (`max_response` 16 MiB, `timeout` 30 s, `max_redirects` 5; `0` returns the 3xx as it is); `web.post_json`. `timeout` covers the exchange after the connection and TLS handshake are made (connecting is bounded by the operating system) because the timer needs the connection to cancel. 301 to 303 turn a POST into a GET. The redirect rule is public as `web.redirect_allowed(from, to)`: a redirect from `https` to `http` cannot be provoked locally (there is no TLS server), so the rule is tested directly and a redirect to `ftp:` is tested through the client.
- **Tests never use the internet.** The real `https://example.com/` scenario is `an_https_request_works_when_online_tests_are_enabled`, which runs only with `BRASA_ONLINE_TESTS=1` (it did not run). `tests/web.rs` also has a Linux run (WSL) of the parity program, the 100-clients and 503 programs, and the write-timeout program. Added `a_write_that_never_finishes_is_given_up_after_write_timeout` for `write_timeout`.
- **Examples.** `examples/rest_api.br` is rewritten on `use web` and `use json` with an in-memory `Map` in a package-level `var` (handlers capture by value, so shared state cannot be a captured local); it needs no `db`. `examples/types.br` already declares `Handler` and `Middleware` exactly as the library does and is a syntax tour (its `Request`, `Response` and `Server` are not defined there), so it is unchanged. `examples/web.br` is new. `tests/package.rs` no longer exempts `rest_api.br` from the check that examples use only existing packages, and `tests/fmt.rs` skips the scramble test for files that use a block form (the lexer used by that test does not know imported block names).
- **Kernel.** `web` is added to the bare-metal rejection list next to `net`; the error is `'web' needs Windows and cannot be used in a bare-metal kernel`.
- **Test results at archive time.** `tests/web.rs` 29/29, `docs`, `fmt`, `package`, `stdlib`, `json`, `comptime`, `parse`, `lsp`, `vscode` and every other file pass, `tests/async.rs` 26/26. Failing and not caused by this change: `tests/ui.rs` 4 (int/long mismatch, pre-existing) and `tests/linux.rs` 5 (`every_library_is_in_the_compatibility_table` names `crypto`, the `poll_io` signature differs between the task layers, `a_large_list_and_many_small_objects`, `a_function_can_be_given_to_c_as_a_callback`, a dns test program that indexes text). The earlier 23 `linux.rs` and 6 `error_kinds.rs` failures are gone now that `task.cur()` exists on Linux.
