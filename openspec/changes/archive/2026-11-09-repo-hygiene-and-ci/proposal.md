## Why

A review of the repository on 2026-11-09 (`docs/project-review-2026-11-09.md`) found that the project's outside face had drifted from its inside: the README roadmap called 15 changes "not started" that were built and archived, and listed a `rename-language` change that does not exist; the README counted about 390 tests when there are more than 1,000; the CHANGELOG announced `0.1.0` with no tag; there was no continuous integration; `cargo clippy` gave 90 warnings; `docs/Zila.docx` was an old Word copy of the README; the tool folders `.claude/`, `.agent/` and `.opencode/` are not versioned and nothing said how to get them back; and the `threads` spec requires Linux behaviour that is not built.

## What Changes

- **README roadmap** replaced by the real gaps, taken from the unchecked tasks of archived changes and from the review. A test makes it unable to drift again: the README may name (in backticks) only changes that are open in `openspec/changes/`, and says "no open changes" exactly when there are none.
- **Release**: the current `[Unreleased]` stays unreleased; `v0.1.0` is tagged on the commit that introduced the `[0.1.0]` section of the CHANGELOG (`f8529fa`, 2026-11-08), not on today's commit, because the commands, extension and docs changed after it. The tag is local until the maintainer pushes it.
- **CI**: `.github/workflows/ci.yml` builds, runs `cargo clippy --all-targets -- -D warnings` and every test target except `async` on Windows and Linux, and runs `async` as its own job.
- **Clippy clean**: 71 warnings fixed by `cargo clippy --fix`, the rest by hand; a few style lints that would make the code worse (`needless_range_loop` on index-parallel loops, `too_many_arguments` on three internal collectors, `wrong_self_convention` on `to_text`, `only_used_in_recursion` in a test generator, `permissions_set_readonly_false` on a Windows-only path) are allowed on the item, not for the crate.
- **`docs/Zila.docx` removed** (stale derivative of the README; it stays in git history).
- **Tool folders**: not versioned (they are generated by the OpenSpec CLI and differ per tool); `CONTRIBUTING.md` says how to recreate them (`openspec init` / `openspec update`).
- **Living specs** that promise more than the code does are marked: `threads` ("Same behavior on Windows and on Linux") now says it is not yet met. `static-linking` was checked: it never received the cache requirement (the archived `add-typed-pipeline-and-cache` and `split-checker-from-emission` kept it out), so it needed no change.

## Capabilities

### New Capabilities
- `continuous-integration`: what the automated checks on every push and pull request are.

### Modified Capabilities
- `docs-sync`: the README roadmap follows `openspec/changes/`.
- `threads`: a requirement is marked as not yet met.

## Impact

`README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `.github/workflows/ci.yml`, `tests/docs.rs`, `openspec/specs/{docs-sync,threads,continuous-integration}`, small edits in `src/` and `tests/` for clippy, `docs/Zila.docx` deleted. No change to the language or to any executable the compiler writes.

Non-goals: fixing the Linux thread layer, finishing the typed pipeline, fuzzing, a security policy (all in the review's later steps).
