## Goals / Non-Goals

**Goals**
- The new name is the single open input; everything else is decided here.
- The rename is mechanical where it can be, listed where it cannot, and verified by tests.
- The rename is rehearsed with a dummy name so that nothing about it is discovered on the real day.

**Non-Goals**
- Choosing the name, or judging it.
- Rewriting history (archived changes, git history) or keeping the old command as an alias.
- Changing the language, the file extension (unless `--ext` is given) or any behavior.
- Renaming the GitHub repository, the Marketplace publisher or the local folder: the tool prints what to do, a person does it.

## Decisions

1. **A script, not a Rust program.** `tools/rename-language.py` uses only the Python standard library, runs before the crate is built (the rename changes the crate), and is easy to read in review. *Alternative:* a `cargo xtask` (type-checked, but it would have to rename its own crate and needs a build first), or a shell one-liner with `sed` (no dry run, no report, quoting problems on Windows).
2. **Case-aware replacement with word-aware identifiers.** The old name is replaced as three forms: `Brasa` → `<Name>`, `brasa` → `<name>`, `BRASA` → `<NAME>`. Identifiers are covered because they contain one of these forms (`brasa_start`, `BrasaWindow`, `BRASA_UI_SCRIPT`, `brasa-parse`). A mixed form such as `bRASA` is reported, not replaced. Words that merely contain the letters (none expected) are caught by the dry run's listing.
3. **Order: moves first, content second, build last.** `git mv` for the three file names, then text replacement, then `cargo build` (which regenerates `Cargo.lock`) and `openspec validate`. Moving first keeps `git log --follow` useful.
4. **Scope by path rules, not by guessing.** Included: tracked text files outside the exclusions. Excluded: `openspec/changes/archive/`, `.git/`, `target/`, `Cargo.lock`, binary files (detected by a NUL byte), and `tools/rename-language.py` itself. The same rules are used by the leftover test (`tests/rename.rs`), which reads them from the script's output (`--print-rules`), so the two cannot disagree.
5. **The story of the name is manual.** The tool recognizes it by markers (the words `ember`, `Brasil`, `mandar brasa`, `Portuguese word`, the 🔥 logo, `Why Brasa`), does not rewrite those lines, and lists them at the end. A person writes the new story; until then the leftover test reports them, which is the intended pressure.
6. **Allow-list in one place.** `tools/rename-allow.txt` lists `path:pattern` pairs the leftover test accepts (for the "formerly known as" note). It is empty before the rename and has one entry after.
7. **Safety rails.** Dry run by default; `--apply` requires a clean working tree (`git status --porcelain` empty) unless `--force`; `--yes` is needed after the checklist is printed; the tool never runs `git commit` or `git push`.
8. **Idempotence.** After applying, the old forms no longer occur, so a second run finds nothing; the tool says so and exits 0.
9. **Rehearsal on a copy.** `git worktree add ../rename-rehearsal` (or a plain folder copy), apply with `Zorbo`, then run: `cargo build`, the whole suite without `tests/async.rs` (as usual), `brasa-parse`→`zorbo-parse --fmt-check`, `node --test editors/vscode/test/*.test.js`, and the Linux tests under WSL. The copy is thrown away. The rehearsal result is recorded in this change.
10. **Extension identity.** The extension id, language id, scope and setting keys change to the new name; the version goes to `0.3.0`. VS Code settings with the old keys stop working (documented); no migration shim, because there is no published version yet.
11. **Repository rename is the last step.** GitHub redirects the old repository URL, so links in the archive and in old issues keep working; the README says where the project lives now.
12. **Claude Code project memory.** The local memory folder is keyed by the project path; after the local folder is renamed the old memory folder is copied to the new key (or the memories are re-saved), noted in the tasks.

## Risks / Trade-offs

- [A replacement lands in text that should keep the old name (a quotation, a Portuguese phrase)] → the dry run lists every changed line, the story markers are excluded, and the diff is reviewed before commit.
- [The new name collides with something (crate, command, publisher)] → the checklist and a pre-flight check before `--apply`; the tool refuses to run if `cargo search` or the Marketplace check was not acknowledged with `--yes`.
- [The rename breaks the docs check, which compares examples and pages] → the rehearsal runs `tests/docs.rs`; `brasa-parse --docs` (renamed) refreshes the blocks if needed.
- [Assembly symbols or generated names are matched by exact strings in tests] → they are renamed with the same rule everywhere, and the rehearsal's full suite and the boot image build prove it.
- [Active changes written by others mention the old name] → they are rewritten by the same rules (their text is plans, not history); the archive is not.
- [The extension tests or docs examples contain the name inside Brasa source strings] → covered by the same replacement; the rehearsal runs them.
- [A half-done rename] → one commit for the rename, one for the manual story, and the leftover test must pass before merging.

## Migration Plan

1. Land this change now (tool, test, checklist, rehearsal). The suite stays green because the leftover test is dormant until a name is given.
2. When the name is chosen: run the checklist, then on a clean tree `python tools/rename-language.py <Name>` (dry run), review, `--apply --yes`.
3. Write the new story (README, GOVERNANCE, site), add the "formerly known as" allow-list entry, run the full suite.
4. Rename the GitHub repository, the local folder and the Marketplace publisher; move the Claude Code memory folder.
5. Rollback: the rename is one commit on a branch; discard the branch.
